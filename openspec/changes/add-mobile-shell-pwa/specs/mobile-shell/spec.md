## Purpose

让产品在手机上长成 App 的样子而不是一张网页：拇指够得到的导航、可以装到主屏、在小屏上版面不塌、断网时已看过的内容还在。这是"先验证再原生"路线里替代原生外壳的那一层。

## ADDED Requirements

### Requirement: 底部主导航

在移动视口下，主导航 MUST 固定在屏幕底部，包含产品的主要去处（广场 / 传递善意 / 我的福袋 / 个人空间）。每个导航项 MUST 有可点击区域不小于常规拇指触达尺寸的热区，MUST 同时有文字标签（不得只有图标）。

顶部 MUST 只保留品牌标识与未读提示，MUST NOT 再承载主导航链接。福袋的未读徽标 MUST 出现在底部导航的对应项上（未读数来源与规则见 `notification`，不变）。

当前所在位置 MUST 在导航上可辨识。

#### Scenario: 手机上的导航位置

- **WHEN** 用户在手机视口下打开任意页面
- **THEN** 主导航固定在屏幕底部、拇指可及，顶部只有品牌与未读提示

#### Scenario: 未读徽标跟着导航走

- **WHEN** 用户有未读的祝福或祈福回应
- **THEN** 底部导航的"我的福袋"项显示未读徽标

#### Scenario: 图标不单独出现

- **WHEN** 检查底部导航的任一项
- **THEN** 它同时有图标与文字标签

### Requirement: 移动优先的版面约束

在 390px 宽的视口下，任何页面 MUST NOT 产生横向滚动。宽内容（长文本、表格、波形、代码样式的诊断行）MUST 在自身容器内滚动或换行，MUST NOT 把整页撑宽。

每个页面的主要操作（提交、发送、录音、回应）MUST 落在屏幕下半部分或随内容可达的位置，MUST NOT 只存在于需要滚动到底才能触达且无任何提示的位置。

表单控件与可点击元素的尺寸 MUST 适合触摸操作，MUST NOT 沿用仅适合鼠标的密集尺寸。

#### Scenario: 小屏不横向滚动

- **WHEN** 在 390px 视口下逐页浏览
- **THEN** 没有任何页面产生横向滚动

#### Scenario: 长内容在容器内滚动

- **WHEN** 一条祝福正文很长或诊断信息很宽
- **THEN** 它在自己的容器里换行或滚动，整页宽度不变

### Requirement: 可安装

产品 MUST 可被安装到手机主屏：提供应用清单（名称、图标、主题色、启动样式）与 Service Worker。从主屏启动时 MUST 以独立窗口呈现，MUST NOT 显示浏览器地址栏。

图标与名称 MUST 使用普世的"祝福 / 善意 / 静心"语言与视觉，MUST NOT 带宗教符号（vision.md 的定位硬约束）。

#### Scenario: 添加到主屏

- **WHEN** 用户在支持的浏览器里把产品添加到主屏并从主屏启动
- **THEN** 以独立窗口打开，没有地址栏，图标与名称正确

#### Scenario: 图标不带宗教符号

- **WHEN** 检查应用图标与名称
- **THEN** 它们使用普世的祝福 / 善意 / 静心语言，不含宗教符号

### Requirement: 离线读降级

断网时，用户已访问过的页面 MUST 仍可打开并显示此前看到的内容或一个明确的离线状态，MUST NOT 显示浏览器的默认错误页。

Service Worker MUST NOT 缓存需要登录才能看到的内容（福袋内容、个人资料、音频）。离线时的写操作（发布、回应、回复）MUST 明确告知当前不可用，MUST NOT 静默失败，也 MUST NOT 排队后在恢复时自动发送。

#### Scenario: 断网打开已访问页面

- **WHEN** 用户断网后打开此前访问过的广场页
- **THEN** 页面可打开并显示离线状态或此前内容，不是浏览器默认错误页

#### Scenario: 不缓存登录内容

- **WHEN** 检查离线缓存的内容
- **THEN** 其中不含福袋内容、个人资料或音频

#### Scenario: 离线写操作明确失败

- **WHEN** 用户在离线状态下尝试提交一条祝福
- **THEN** 系统明确告知当前不可用，不静默失败，也不在恢复网络后自动发送
