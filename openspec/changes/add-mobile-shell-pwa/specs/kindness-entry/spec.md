## MODIFIED Requirements

### Requirement: 首屏呈现真实的善意

**入口页**（用户打开产品后落地的第一个页面；其具体路由与导航位置由 `mobile-shell` 决定，移动端为底部导航的第一项）MUST 呈现至少一条当前 `published` 的真实祈福，包含作者的粗粒度信息（或匿名标识）、处境描述摘录，以及该祈福**最新一条回应的正文摘录**（若已有回应）。入口页 MUST NOT 用范例、样例或占位文案冒充真实内容。

当入口页同时呈现一条被选中的祈福与其它祈福的列表时，被选中的那条 MUST 在视觉层级上明显重于列表项——入口页的作用是让人**读进去一条**，MUST NOT 退化为一个无重点的列表。

当广场上没有任何 `published` 祈福时，入口页 MUST 展示一个说明当前还没有祈福的中性状态，并给出"发布一条祈福"与"给附近的人写一段祝福"两个入口，MUST NOT 展示空白或报错。

入口页的呈现 MUST 对未登录访客与登录用户一致（登录用户额外可见自己的未读提示）。

#### Scenario: 访客打开首页

- **WHEN** 未登录访客打开产品的入口页，广场上有已发布的祈福
- **THEN** 首屏就能读到一条真实祈福的处境摘录和它最新一条回应的正文摘录，无需登录、无登录墙

#### Scenario: 被选中的那条有视觉重点

- **WHEN** 入口页同时展示被选中的祈福与其它祈福的列表
- **THEN** 被选中的那条在版面上明显更重，不是列表里加粗的第一项

#### Scenario: 广场为空

- **WHEN** 广场上还没有任何 `published` 祈福
- **THEN** 入口页展示中性的空状态与两个入口，不展示空白页也不报错

#### Scenario: 不用假内容占位

- **WHEN** 入口页需要展示一条祈福
- **THEN** 展示的是真实用户发布的祈福，不是范例或样例文案

### Requirement: 首次善意的最短路径

从**入口页**开始，一个未登录用户完成"给某人送出第一段善意"MUST 至多经过 **2 次主动操作**（不含登录本身与输入内容）：在入口页就地进入回应入口，然后提交。系统 MUST NOT 在这条路径上插入必须完成的画像填写、受众筛选、预览或范本步骤。

回应祈福与群发祝福两条路径都 MUST 满足这条约束。群发路径的受众条件 MUST 有可用默认值（见 `blessing-audience` 的"撰写页的默认受众条件"）。

#### Scenario: 从首页到送出

- **WHEN** 访客在入口页点开回应入口，写下一段祝福并提交
- **THEN** 除登录外不需要任何其它前置步骤，这段祝福被送出

#### Scenario: 不强制填画像

- **WHEN** 用户从未设置过位置 / 性别 / 出生年 / 标签，试图回应一条祈福
- **THEN** 系统不要求先补全画像，回应正常提交
