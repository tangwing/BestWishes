- [ ] 1.3 审核台从主导航移除，改为个人空间内的入口。**在代码注释里写明：这只是不显眼，不是权限门禁——RBAC 仍是 B-65 待评审**（design 风险项，防后人误以为已有门禁）
- [ ] 1.4 退出按钮挪进个人空间
- [ ] 1.5 顶部只留品牌 + 未读提示。**改之前先看 B-86 那次提交的意图**（用户名要在右上角），别在重排时又把它推回 nav 中间
- [ ] 1.6 未读徽标迁到底部"我的福袋"项；e2e 断言有未读时徽标出现在底部导航上

## 3. 可安装（PWA）

- [ ] 3.1 `manifest.json`（名称、图标、主题色、`display: standalone`）+ 图标资产；图标与名称用普世的祝福 / 善意 / 静心语言，**不带宗教符号**（vision.md 定位硬约束）
- [ ] 3.2 Service Worker 注册 + 更新策略（新版本可用即激活并提示刷新）
- [ ] 3.3 缓存白名单：应用外壳 + 显式列出的**公开**路径。**默认不缓存**——漏掉白名单只是少缓存一页，漏掉黑名单就是泄露（design D6）
- [ ] 3.4 测试断言缓存里不含福袋内容、个人资料、音频
- [ ] 3.5 离线时的写操作明确告知不可用，不静默失败、不排队自动重发
- [ ] 3.6 **准备好 SW 的注销路径**并验证可用——SW 一旦上线，回滚要额外发一版能自我注销的 SW（design 迁移计划第 2 条，本变更唯一"回滚比上线复杂"的部分）
- [ ] 3.7 `docs/DEMO.md` 写清"看不到改动先清一次 SW"——**不写这条，后面每轮走查都会浪费时间在假 bug 上**（design 风险项）

## 4. 推送通道：订阅

- [ ] 4.1 推送订阅表（用户 × 设备端点）+ 内存与 PGlite 两套仓储实现，契约一致
- [ ] 4.2 VAPID 密钥走环境变量，**不进仓库**；缺配置时推送整体降级为不可用，站内一切照常——这条要有测试
- [ ] 4.3 个人空间的推送开关：授权 / 关闭；关闭时移除订阅
- [ ] 4.4 拒绝或从未授权时站内未读徽标与通知列表照常工作，**且系统不反复索要授权**；测试断言之

## 5. 推送通道：发送

- [ ] 5.1 在 `notification-service` 产生通知后发推送，**包在不会向外抛的边界里**（design D4）；用 fake sender 单测，真实推送在 e2e 里无法稳定验证（沿用 `audio-scoring` 的 fake provider 模式）
- [ ] 5.2 **先写失败测试**：推送发送抛异常时，站内通知仍然产生、未读数仍然增加——这是 spec 的硬约束，必须有证据
- [ ] 5.3 推送文案拼装处**只拿得到 id 和类型，拿不到正文**（design D5：靠结构保证，不靠写文案的人自觉）；测试断言推送体不含任何原文
- [ ] 5.4 端点返回 410 / 404 时删除该订阅，不再重试；测试覆盖
- [ ] 5.5 站内 4 秒轮询**保留**（design D3：推送是增强，轮询是地板），确认两者并存时未读数始终以接口为准、不会错乱
