## MODIFIED Requirements

### Requirement: 受众预览

系统 SHALL 提供受众预览：返回命中总人数、群发人数上限、以及距离最近的若干位（昵称、城市、距离、年龄）。预览结果 MUST NOT 包含发送者自己、没有位置的人、范围外的人。预览 MUST NOT 泄露候选人的精确经纬度或 openid。

受众预览 MUST 是**可选的辅助信息，不是发送的前置步骤**。系统 MUST NOT 要求用户先取得一次预览结果才允许提交群发；提交按钮的可用性 MUST NOT 依赖预览是否执行过。人数区间的实际约束由服务端在提交时执行（见"群发人数上限"），与是否预览无关。

#### Scenario: 预览命中人数

- **WHEN** 发送者预览一个范围，范围内有 2 个符合条件的陌生人
- **THEN** 系统返回 `count = 2`，并给出这 2 人的昵称 / 城市 / 距离 / 年龄样本

#### Scenario: 不预览直接发送

- **WHEN** 用户写完正文、从未点击过预览，直接提交群发
- **THEN** 系统照常受理，按提交时的受众条件执行人数上限校验

#### Scenario: 预览失败不阻断发送

- **WHEN** 预览接口调用失败
- **THEN** 用户仍可提交群发，最终结果由服务端提交时的校验决定

## ADDED Requirements

### Requirement: 撰写页的默认受众条件

撰写群发祝福时，系统 MUST 提供一组开箱可用的默认受众条件，使用户**不触碰任何筛选控件也能完成一次群发**。默认条件 MUST 是一个合理的近距离范围，且 MUST NOT 默认带上年龄、性别或标签中的任何一项——留空的条件不会把没填相应画像的人排除在外。

筛选控件 MUST 默认收起，展开后才呈现完整的距离 / 年龄 / 性别 / 标签设置。用户调整过的条件 MUST 在本次撰写过程中保持。

#### Scenario: 不碰筛选器直接发

- **WHEN** 用户进入撰写页，只写正文就提交
- **THEN** 系统按默认受众条件执行群发，不因"没选受众"而拒绝

#### Scenario: 默认不带年龄性别标签

- **WHEN** 用户进入撰写页，未展开筛选控件
- **THEN** 生效的受众条件里年龄、性别、标签均为空，不会排除画像不完整的候选人

#### Scenario: 展开后可精调

- **WHEN** 用户展开筛选控件并把距离改小
- **THEN** 本次撰写后续使用的是用户调整后的条件
