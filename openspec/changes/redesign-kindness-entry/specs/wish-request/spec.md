## MODIFIED Requirements

### Requirement: 撰写祈福

登录用户 SHALL 可撰写一条祈福，内容包含处境 / 心事描述（必填正文）、一段可选的具体稿子（`scriptText`，供回应者朗读）、一组可选标签（供 `wish-request-matching` 按标签推荐候选响应人；留空表示不按标签限定），以及一个**可选的匿名标记**（`anonymous`，默认关闭）。正文长度约束与祝福正文一致（复用 `blessing-authoring` 的字数规则）。祈福 MUST 先过内容安全检查（复用 `content-moderation` 的 `ModerationProvider`），判定逻辑与祝福正文一致：命中 `violation` MUST 拒绝发布；命中 `suspect` MUST NOT 直接公开或触发匹配推送，而是进入人工复核队列，通过后才正式公开（见"祈福的生命周期"）；只有 `pass` 才立即公开。

勾选匿名的祈福，在广场列表、详情页与匹配通知中 MUST 以中性标识（"一位朋友"）代替作者昵称，且 MUST NOT 展示作者城市。匿名 MUST 只影响对外展示：系统内部 MUST 仍关联真实作者，作者本人的"我的祈福"筛选、撤回 / 删除、收取回应、以及人工复核工单指向的责任主体全部不受影响。匿名标记 MUST 在发布时确定，发布后 MUST NOT 可切换（避免已公开内容的身份前后不一致）。

#### Scenario: 附稿子发布

- **WHEN** 用户撰写祈福时填写了处境描述和一段稿子
- **THEN** 系统保存两者，发布后回应者在响应页能看到这段稿子

#### Scenario: 不附稿子发布

- **WHEN** 用户只填写处境描述，不提供稿子
- **THEN** 系统正常发布，回应者只看到处境描述，自由发挥响应内容

#### Scenario: 匿名发布

- **WHEN** 用户勾选匿名后发布一条祈福
- **THEN** 广场列表和详情页显示作者为"一位朋友"、不显示城市；该祈福仍出现在作者自己的"我的祈福"筛选里，仍可撤回

#### Scenario: 匿名不影响审核追责

- **WHEN** 一条匿名祈福命中 `suspect` 进入人工复核队列
- **THEN** 工单仍关联真实作者，复核人员的处置对象与非匿名祈福一致

#### Scenario: 发布后不可切换匿名

- **WHEN** 作者尝试把一条已发布祈福的匿名标记改掉
- **THEN** 系统拒绝该操作

#### Scenario: 祈福内容命中违规

- **WHEN** 一条祈福的处境描述或稿子命中内容安全检查的 `violation`
- **THEN** 祈福被拒绝发布，作者看到拒绝原因

#### Scenario: 祈福内容命中疑似

- **WHEN** 一条祈福的处境描述命中内容安全检查的 `suspect`（如拉客 / 敛财话术）
- **THEN** 祈福进入 `pending_review`，不出现在广场，不触发候选人匹配推送；同一条工单出现在人工复核队列（复用 `content-moderation` 的统一队列，不新建一套）

### Requirement: 祈福广场列表

系统 SHALL 提供一个公开的祈福广场，列出所有 `published` 状态的祈福。广场列表 MUST 对未登录访客可读；响应、发布、回复等写操作 MUST 要求登录。广场列表 SHALL 按发布时间倒序分页。

广场列表的每一项 MUST 包含：作者的粗粒度信息（昵称、城市；匿名祈福为"一位朋友"且无城市）、处境描述（可截断）、标签、聚合统计（见"回应数聚合统计"），以及**该祈福最新一条 `published` 回应的正文摘录**（可截断；音频回应取其转写文本；尚无回应时为空）。

该摘录 MUST 由写入路径维护，与 `responseCount` / `lastResponseAt` 同一时机更新，MUST NOT 在列表渲染时遍历回应表。当最新那条回应离开 `published`（撤回 / 下架 / 删除）时，摘录 MUST 相应更新为新的最新一条，或在没有剩余回应时清空。

列表项 MUST NOT 包含回应的音频链接、回应者身份、或除最新一条摘录以外的任何回应正文——完整回应列表只在祈福详情页（见"查看祈福详情"）返回。

#### Scenario: 浏览广场

- **WHEN** 用户打开祈福广场
- **THEN** 看到当前公开的祈福列表，按最新发布排在前面，每项显示处境摘要、标签、"已收到 N 条回应"、以及最新一条回应的正文摘录

#### Scenario: 未登录浏览广场

- **WHEN** 未登录访客打开祈福广场
- **THEN** 可以看到列表内容（含最新回应摘录），但尝试响应时被引导先登录

#### Scenario: 尚无回应的祈福

- **WHEN** 一条祈福还没有收到任何回应
- **THEN** 列表项显示"还没有回应"，不显示摘录位

#### Scenario: 最新回应被撤回后摘录更新

- **WHEN** 一条祈福最新的那条回应被撤回，该祈福还有更早的回应
- **THEN** 列表项的摘录变为剩下的最新一条；若已无任何 `published` 回应，摘录清空

#### Scenario: 列表不泄露回应内容

- **WHEN** 一条祈福已经收到若干条回应，任何人打开广场列表
- **THEN** 列表项只显示回应数量与最新一条的正文摘录，不包含回应者昵称、音频 URL，也不包含其它回应的正文

### Requirement: 查看祈福详情

系统 SHALL 提供祈福详情视图。详情 SHALL 返回祈福的处境描述全文、可选稿子、标签、聚合统计，以及该祈福收到的全部 `published` 回应（不设数量上限，按时间倒序），每条回应包含回应者的粗粒度信息（昵称、城市，规则同 `blessing-authoring` 的"发送者信息来自画像"）与回应内容。未过审 / 已撤回的回应 MUST NOT 出现在详情里。匿名祈福的作者信息按"撰写祈福"的规则以"一位朋友"呈现。

详情的**文字内容**（处境全文、稿子、每条回应的正文 / 转写、往返回复）MUST 对未登录访客可读。**音频回放 MUST 要求登录**：详情视图 MUST NOT 向未登录访客下发音频链接，而是给出一个可辨识的"登录后可收听"状态。

音频回放的权限模型：当一条音频祝福是某条 `published` 祈福的回应时，**任何登录用户** SHALL 可回放它（它已经作为公开内容出现在详情页，回放权限必须与之一致）。其它场景的音频（如 P1 群发的音频祝福）MUST 维持"仅作者与收件人"的限制不变。

回应内容 MUST 只在详情视图返回，MUST NOT 出现在广场列表（最新一条的正文摘录除外，见"祈福广场列表"）。祈福作者与其他登录用户看到的回应集合一致（都是 `published` 的那些）；回应者的多维评分细节 MUST NOT 对任何人在此暴露（见 `audio-scoring` 的"请求人看到的反馈"）。

#### Scenario: 点进详情看到回应

- **WHEN** 登录用户在广场点开一条已收到 3 条回应的祈福
- **THEN** 详情页展示处境全文、稿子，以及这 3 条回应的音频与转写，可逐条播放

#### Scenario: 访客读得到文字

- **WHEN** 未登录访客打开一条祈福详情
- **THEN** 能读到处境全文、稿子、每条回应的文字 / 转写与往返回复

#### Scenario: 访客听不到音频

- **WHEN** 未登录访客打开一条含音频回应的祈福详情
- **THEN** 音频位显示"登录后可收听"，响应体中不含音频链接

#### Scenario: 第三方登录用户可回放公开回应

- **WHEN** 一个既不是祈福作者、也不是回应者的登录用户，在详情页播放某条回应的音频
- **THEN** 音频正常回放，不返回权限错误

#### Scenario: 群发音频仍受限

- **WHEN** 一个既非作者也非收件人的登录用户，尝试回放一条 P1 群发的音频祝福
- **THEN** 系统拒绝，权限规则不变

#### Scenario: 详情不含评分细节

- **WHEN** 祈福作者查看自己某条祈福的详情
- **THEN** 看到每条回应的内容，但看不到回应者的完整度 / 专注度 / 真诚度标签

#### Scenario: 撤回的回应不出现在详情

- **WHEN** 某条回应被作者撤回后，任何人打开该祈福详情
- **THEN** 这条回应不在列表中，`responseCount` 也已相应减少
