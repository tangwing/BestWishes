## Why

BestWishes 需要一个能验证核心体验循环的最小可用版本：一个人静下心来，为另一个人认真写一段带个人心意的祝福，并把它送达。P1 只做文本、不做 AI 评估、不做任何资金功能（见 [concept.md](../../../docs/product/concept.md) 的「P1 范围（已锁定）」），用最小的活动部件把"写祝福 → 平台校验 → 送达 → 被看见"这条链路跑通，为 P2（音视频 + AI 用心反馈 + 祝福请求）打地基。

## What Changes

- 新增微信网页授权登录与最小用户资料（昵称、头像、注册来源）。
- 新增**个人空间**：预设落款与城市、定位授权开关（P1 占位）、"精选展示"个人默认偏好、退出登录、坚持记录入口。
- 新增《用户内容与授权协议》与逐版本、逐项的同意记录（送达【必选】/ 精选展示【默认跟随个人偏好或系统默认，可关】/ 未来合成【告知】）。
- 新增祝福范本库（运营维护，含"宗教敛财护栏"词校验）——**只作参考，不能一键套用**。
- 新增文本祝福撰写：正文（**须自己录入，粘贴进正文被拦截**）+ 三项发送者信息（给谁必填、落款、城市，后两项默认取个人空间）+ 不打扰的静心与"发心"引导；草稿自动保存。
- 新增「发布即校验、延迟送达」模型：作者提交即"已发送"并拿到公开短链；平台 hold 住接收方可见性，自动内容合规检查通过后访客才可见。
- 新增祝福状态机（`draft / verifying / published / rejected / taken_down / withdrawn / deleted / expired`）与作者管理（撤回、重新发布、删除、续期）。
- 新增可分享的祝福卡片 / 落地页：访客免注册查看；按状态渲染正文或中性占位；链接设默认有效期。
- 新增自动内容合规检查（可插拔 `ModerationProvider`，P1 用规则实现）与人工复核队列（疑似 / 举报 / 申诉统一工单）。
- 新增举报入口（匿名可提交 + 防滥用）。
- 新增坚持记录（按作者所在地区自然日聚合"已发布且有效"的祝福数；撤回 / 删除 / 下架即时回撤，链接过期不回撤）。
- 新增**收发记录**：发件箱（P1 完整——我写给别人的祝福）+ 收件箱（P1 为空状态，结构与入口先立起来，P2 点亮）。
- **非目标（P1 明确不做）**：音视频、AI 用心 / 质量评分、祝福请求 / 匹配 / 推荐、悬赏与资金、站内 user→user 定向送达（收件箱在 P1 为空）、合成视频、原生 App、访客一键致意（移至 P4）、定位自动获取城市（P1 占位）。

## Capabilities

### New Capabilities

- `wx-account`: 微信网页授权登录、会话、最小用户资料（昵称 / 头像 / 来源）、openid 幂等。
- `user-profile`: 个人空间——预设落款与城市、定位授权开关（P1 占位）、精选展示个人默认偏好、退出登录、坚持记录入口、注销发起。
- `content-agreement`: 《用户内容与授权协议》条款展示、版本管理、逐项同意记录、精选展示默认值（个人偏好 > 系统默认）。
- `blessing-authoring`: 范本库（只作参考、不可一键套用）、自由创作、正文须自己录入（拦粘贴）、三项发送者信息、静心与发心引导、草稿保存与恢复。
- `blessing-delivery`: 祝福状态机、发布即校验 / 延迟送达、公开短链与落地页、访客免注册查看（正文 / 占位）、撤回 / 校验期取消 / 重新发布 / 删除 / 续期、链接有效期。
- `blessing-records`: 收发记录——发件箱（P1 完整）、收件箱（P1 空状态 + 结构预留）。
- `content-moderation`: 可插拔 `ModerationProvider`、规则实现、自动检查三档判定、人工复核队列与工单状态机、举报提交与防滥用、复核动作对祝福状态机的驱动。
- `blessing-streak`: 按地区自然日聚合的坚持记录、加计数与回撤规则（过期不回撤）、连续天数计算、仅作者可见。

### Modified Capabilities

（无——当前 `openspec/specs/` 为空，P1 全部为新增能力。）

## Impact

- **代码**：新建前端（React + TS + Vite PWA）、后端（Node + TS + HTTP API）、PostgreSQL 数据模型，见 [ADR 0003](../../../docs/adr/0003-p1-tech-stack-web-first.md)（Proposed）与 [P1 架构设计](../../../docs/architecture/p1-architecture.md)。当前仓库无产品代码，P1 建立 `client/` 与 `server/` 目录（AGENTS.md §5 目录表届时更新）。
- **依赖**：新增 React、Vite、后端 HTTP 框架、PostgreSQL 驱动、测试框架（Vitest）。均为 P1 必需，非"以防将来"。
- **外部账号（P1 不强制打通，接口预留）**：微信开放平台 / 公众号 appid+secret；真实内容安全 API（阿里云 / 腾讯云 / 网易易盾）。P1 用 stub / 规则实现，验收不依赖真实第三方账号。
- **合规**："精选展示"默认开启的合规性待法务确认（见 use-cases 开放问题 1 / 调研 ADR-M）；代码把默认值做成可翻转配置。
- **待架构评审**：见 [P1 架构设计](../../../docs/architecture/p1-architecture.md) §10。
