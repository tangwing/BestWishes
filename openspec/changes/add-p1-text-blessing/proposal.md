## Why

BestWishes 是一个**陌生人之间**的善意平台。P1 要验证的核心循环是：一个人静下心来写一段祝福，选一个受众范围（附近、某个年龄段、某类标签的人），把它群发给这些**素不相识的人**；收到的人在收件箱看到、收到通知，只能回一段祝福——不能聊天。P1 只做文本（音视频形态留白）、不做 AI 评估、不做资金、不做祝福请求 / 匹配（移至 P2）。见 [ADR 0004](../../../docs/adr/0004-p1-stranger-broadcast-model.md)。

> 2026-09-04：本 change 从「作者写给认识的人 → 生成分享链接」重定为「按条件群发给陌生人 → 收件箱 + 通知」。下述条目为**重定后**的完整范围。

## What Changes

- 新增微信网页授权登录与最小用户资料（昵称、头像、注册来源）。
- 新增**个人画像**：昵称 / 落款、城市（显示用）、**经纬度位置**（浏览器 Geolocation 或手填）、性别、出生年、**标签**——画像用于被别人的受众筛选命中。
- 新增《用户内容与授权协议》与逐版本、逐项的同意记录（**群发送达**【必选】/ 精选展示【可关】/ 未来合成【告知】）。
- 新增祝福范本库（运营维护，含拉客 / 敛财护栏词校验）——**只作参考，不能一键套用**。
- 新增文本祝福撰写：形式 tab（P1 只 `text`，`audio` / `video` 留白）+ 正文（**须自己录入，粘贴被拦截**）+ 静心与"发心"引导；草稿自动保存（正文 + 场景 + 受众）。
- 新增**受众筛选 + 预览**：以发送者位置为圆心的距离半径 + 年龄区间 + 性别 + 标签（命中任一）；预览返回命中人数、上限、距离最近的样本。
- 新增**按条件群发**：命中人数 ∈ [1, `maxAudienceSize`]（默认 10）才可发；提交时定格收件人列表（快照）。
- 新增「发布即校验、延迟送达」+ **投递扇出**：提交即"已发送"，内容校验通过后逐个投递到收件人的收件箱 + 发通知（幂等靠 `deliveredAt`）。
- 新增祝福状态机（`draft / verifying / published / rejected / taken_down / withdrawn / deleted / expired`）与发送者管理（撤回、重新发布、删除、续期）。
- 新增**收件箱**：收到的祝福按状态渲染（正文 / 占位），显示发送者昵称 + 城市 + 大致距离；不暴露精确位置 / openid。
- 新增**站内通知**：`blessing_received` 通知 + 未读徽标（P1 无真实推送通道）。
- 新增**回一段祝福**：`scope=reply`，受众恒为对方一人，同样过校验；无会话、无聊天。
- 新增公开链接 `/p/:slug`：访客免注册按状态查看正文或占位——用途是**传播**（转发带人来平台），不是送达机制。
- 新增自动内容合规检查（可插拔 `ModerationProvider`，P1 规则实现，目标是**过滤无效 / 垃圾 / 违规**）+ 人工复核队列（疑似 / 举报 / 申诉统一工单）。
- 新增举报入口（匿名可提交 + 防滥用）。
- 新增**回响**（原"坚持记录"）：按发送者地区自然日聚合"已发布且有效"的祝福数；撤回 / 删除 / 下架即时回撤，链接过期不回撤；仅本人可见、无排行无积分。
- **非目标（P1 明确不做）**：语音 / 视频祝福、AI 用心 / 质量评分、祝福请求 / 匹配 / 推荐（移至 P2）、悬赏与资金、逆地理编码、真实推送通道、合成视频、原生 App、访客一键致意（移至 P4）、距离查询空间索引。

## Capabilities

### New Capabilities

- `wx-account`: 微信网页授权登录、会话、最小用户资料（昵称 / 头像 / 来源）、openid 幂等。
- `user-profile`: 个人画像——昵称 / 落款、城市、经纬度位置、性别、出生年、标签；`canBroadcast` 判定；退出登录、注销发起。
- `content-agreement`: 《用户内容与授权协议》条款展示、版本管理、逐项同意记录、`alreadyConsented` 查询、精选展示默认值。
- `blessing-authoring`: 形式选择（text / 留白）、范本库（只作参考、不可一键套用）、正文须自己录入（拦粘贴）、静心与发心引导、草稿保存与恢复。
- `blessing-audience`: 受众筛选（距离 / 年龄 / 性别 / 标签）、受众预览（命中数 + 上限 + 样本）、人数上限约束、提交时定格收件人快照。
- `blessing-delivery`: 祝福状态机、发布即校验 / 延迟送达、首次 published 时投递扇出（幂等）、收件箱按状态渲染、回一段祝福、公开链接 + 访客查看、撤回 / 校验期取消 / 重新发布 / 删除 / 续期、链接有效期。
- `notification`: `blessing_received` 站内通知、未读数、标记已读。
- `blessing-records`: 发件箱（发出的祝福 + 状态 + 收件人数）。
- `content-moderation`: 可插拔 `ModerationProvider`、规则实现（无效 / 垃圾 / 违规三档判定）、人工复核队列与工单状态机、举报提交与防滥用、复核动作对状态机与投递的驱动。
- `blessing-streak`: 回响——按地区自然日聚合，加计数与回撤规则（过期不回撤），仅本人可见。

### Modified Capabilities

（无——`openspec/specs/` 为空，P1 全部为新增能力。上文所列即重定后的目标状态。）

## Impact

- **代码**：新建前端（React + TS + Vite PWA）、后端（Node + TS + HTTP API）、PostgreSQL 数据模型，见 [ADR 0003](../../../docs/adr/0003-p1-tech-stack-web-first.md)（Proposed）与 [P1 架构设计](../../../docs/architecture/p1-architecture.md)。当前仓库无产品代码，P1 建立 `client/` 与 `server/` 目录（AGENTS.md §5 目录表届时更新）。
- **依赖**：新增 React、Vite、后端 HTTP 框架、PostgreSQL 驱动、测试框架（Vitest）。均为 P1 必需，非"以防将来"。
- **外部账号（P1 不强制打通，接口预留）**：微信开放平台 / 公众号 appid+secret；真实内容安全 API（阿里云 / 腾讯云 / 网易易盾）。P1 用 stub / 规则实现，验收不依赖真实第三方账号。
- **合规**："精选展示"默认开启的合规性待法务确认（见 use-cases 开放问题 1 / 调研 ADR-M）；代码把默认值做成可翻转配置。
- **待架构评审**：见 [P1 架构设计](../../../docs/architecture/p1-architecture.md) §10。
