## Purpose

对祝福文本做安全合规检查（只判安全违规，不评判质量好坏），把疑似内容、举报和申诉汇入统一的人工复核队列，复核结论驱动祝福状态机。

## ADDED Requirements

### Requirement: 可插拔的内容审核接口

系统 SHALL 通过一个统一接口 `ModerationProvider` 做内容审核，输入为祝福文本（音视频形态传转写），输出为三档结论（`pass` / `suspect` / `violation`）与命中大类。审核实现 MUST 可替换（P1 用规则实现，真实内容安全 API 作为后续实现），替换 MUST NOT 改变调用方契约。

#### Scenario: 更换审核实现

- **WHEN** 运营将审核实现从规则实现切换为云 API 实现
- **THEN** 祝福提交、校验、落地页行为不变，调用方无需改动

### Requirement: 自动检查的三档判定

自动检查 MUST 把每条待发布祝福判为三档之一并驱动 `blessing-delivery` 的状态转移：`pass` → 投递；`suspect` → 保持校验中并建复核工单；`violation` → 驳回。命中违禁 / 敏感（涉政、色情、仇恨、诈骗、违法）MUST 判 `violation`；明显无效内容（刷屏、空、全标点）MUST 判 `violation`。站外导流（链接、联系方式）与拉客 / 敛财话术 MUST 至少判 `suspect`。审核服务超时 / 不可用 MUST 采取保守策略（维持 hold + 进人工队列），MUST NOT 默认放行。审核只判安全 / 有效性，MUST NOT 评判祝福"写得好不好"。

#### Scenario: 命中违禁词

- **WHEN** 一条祝福正文命中违禁词表
- **THEN** 检查结论为 `violation`，祝福被驳回

#### Scenario: 命中拉客 / 敛财护栏词

- **WHEN** 一条祝福出现"超度收费""加我微信"类导流 / 敛财表述
- **THEN** 检查结论至少为 `suspect`，祝福保持校验中并进入人工复核队列

#### Scenario: 明显无效内容

- **WHEN** 一条祝福正文是同一个字刷屏或全是标点
- **THEN** 检查结论为 `violation`，祝福被驳回，不占用人工队列

#### Scenario: 审核服务不可用

- **WHEN** 内容审核在提交时不可用
- **THEN** 祝福保持 `verifying` 并进入人工复核队列，不对访客可见

### Requirement: 统一人工复核队列

系统 SHALL 维护一个复核工单队列，来源包括：自动疑似、用户举报、用户申诉。工单 MUST 记录目标祝福、来源、大类、状态、处理人、理由与时间线。队列 MUST 按优先级排序：高危举报 > 用户申诉 > 自动疑似 > 随机抽检。每个进入队列的工单 MUST 有终态（通过 / 下架 / 要求修改）。

#### Scenario: 复核通过

- **WHEN** 审核员对一条自动疑似工单判"通过"
- **THEN** 目标祝福转为 `published`，工单关闭并留痕处理人、时间、理由

#### Scenario: 复核下架

- **WHEN** 审核员对一条已发布祝福判"下架"
- **THEN** 目标祝福转为 `taken_down`，作者收到通知（含大类原因与申诉入口）

#### Scenario: 申诉二次被驳回

- **WHEN** 一条工单的申诉被资深审核员二次驳回
- **THEN** 工单关闭为终态并告知作者最终结果

### Requirement: 举报

系统 SHALL 允许访客或登录用户对一条祝福提交举报，选择举报大类并可补充说明。举报 MAY 匿名提交，但系统 MUST 记录必要的防滥用信息（频率、指纹）。同一来源对同一祝福的重复举报 MUST 合并计数、不重复建单。高危大类（涉嫌违法 / 严重冒犯）MUST 触发对该祝福的即时临时下架待复核。举报人 MUST NOT 获知被举报作者的身份信息。

#### Scenario: 匿名举报高危内容

- **WHEN** 未登录访客以"涉嫌违法"大类举报一条已发布祝福
- **THEN** 该祝福在约定时限内转为占位页（临时下架），并生成高优先级复核工单

#### Scenario: 重复举报合并

- **WHEN** 同一访客对同一祝福连续多次提交举报
- **THEN** 系统合并为一条工单并累加计数，不新建工单

### Requirement: 抽检与校准

系统 SHALL 支持对已自动通过的内容做可配置比例的随机抽检，抽检结果 MUST 被记录，用于校准自动检查阈值。

#### Scenario: 随机抽检

- **WHEN** 抽检比例配置为非零
- **THEN** 相应比例的已通过祝福被加入复核队列的"随机抽检"优先级，结果留痕

### Requirement: 审核不做质量评判

内容审核 MUST 只做安全合规判定，MUST NOT 产出用心 / 质量分数，MUST NOT 因内容"不够好"而阻止送达。

#### Scenario: 平淡但合规的祝福

- **WHEN** 一条内容平淡、无个性化、但不违规的祝福提交
- **THEN** 自动检查结论为 `pass`，祝福正常送达
