## Purpose

像邮箱一样，给用户一个"收发记录"：发件箱（我写给别人的祝福）和收件箱（别人送给我的祝福）。P1 的发件箱是完整的；收件箱把结构和入口立起来，等 P2 的主动赠送 / 祝福请求点亮。

## ADDED Requirements

### Requirement: 收发两个视图

"收发记录" SHALL 分为**发件箱**（送出的）和**收件箱**（收到的）两个视图，用户可切换。发件箱 MUST 展示用户创作的全部祝福（不含已删除），带状态、场景、给谁、时间。

#### Scenario: 查看发件箱

- **WHEN** 作者进入收发记录
- **THEN** 默认展示发件箱，列出自己创作过的祝福及其当前状态

#### Scenario: 从发件箱管理祝福

- **WHEN** 作者在发件箱选中一条祝福
- **THEN** 可对其执行 `blessing-delivery` 定义的管理操作（撤回 / 取消 / 重新发布 / 删除 / 续期）

### Requirement: 收件箱（P1 为空状态）

收件箱 SHALL 存在且可访问。P1 阶段站内没有 user→user 送达，收件箱 MUST 展示一个说明性的空状态（大意："你写给别人的祝福通过链接送达；站内收发要等主动赠送和祝福请求上线"），MUST NOT 报错或隐藏入口。

#### Scenario: P1 打开收件箱

- **WHEN** 用户在 P1 切到收件箱
- **THEN** 看到友好的空状态说明，而不是错误或空白页

> 收件箱的数据模型（谁送的、什么时候、关联哪条祝福）在架构设计里预留，P2 填充。
