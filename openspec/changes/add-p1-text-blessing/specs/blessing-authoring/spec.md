## Purpose

让登录用户静下心来，用自己的话写一段文本祝福：范本只作参考、不能一键套用，附带少量发送者信息，撰写过程有不打扰的静心引导和"发心"提示，未提交的内容以草稿形式保留。

## ADDED Requirements

### Requirement: 范本库（只作参考）

系统 SHALL 提供按场景分类的祝福范本（至少覆盖生日、节日、鼓励、康复祈愿、纪念 / 追思、日常问候，每类不少于 3 条），每条含起草提示和示例文字。范本 MUST 只作参考展示——**不提供一键填入正文的操作**，用户须自己录入。运营维护的每条范本 MUST 通过"宗教敛财护栏"词校验（不得含"宗教服务 / 代祷收费 / 超度 / 消灾解厄"等表述）。

#### Scenario: 范本不能一键套用

- **WHEN** 用户查看一条范本
- **THEN** 系统展示它的提示与示例供参考，但没有"用这个"之类把示例填进正文的按钮

#### Scenario: 范本库加载失败

- **WHEN** 范本库加载失败
- **THEN** 系统允许用户直接进入自由创作

#### Scenario: 范本含护栏词

- **WHEN** 运营尝试发布一条含"代祷收费"表述的范本
- **THEN** 系统拒绝发布并提示命中护栏词

### Requirement: 正文须自己录入

祝福正文 MUST 由用户自己录入。系统 MUST 阻止把文本直接粘贴进正文输入框，并给出温和提示（大意："用你自己的话写出来，对方会感受到不一样"），提示 MUST NOT 是阻断式弹窗。语音输入、输入法候选等正常录入方式不受影响。

#### Scenario: 粘贴进正文被拦截

- **WHEN** 用户尝试把一段文本粘贴进祝福正文输入框
- **THEN** 系统不接受这次粘贴，给出温和提示，用户可继续自己打字

> 备注：此规则的无障碍与"改错想重贴一小段"场景待复查（BACKLOG B-06），P1 先上简单版。

### Requirement: 文本祝福撰写

祝福 MUST 包含非空的祝福正文。正文长度 SHALL 有下限与上限约束（具体数值可配置，默认 15–500 字）。系统 MUST 在正文为空、低于下限或超过上限时阻止提交并明确提示。

#### Scenario: 正文过短

- **WHEN** 用户提交的正文低于长度下限
- **THEN** 系统阻止提交并提示补充

### Requirement: 祝福形式（内容形态留白）

祝福 SHALL 有一个内容形态字段 `contentType`，取值 `text` / `audio` / `video`。P1 只允许创作 `text`；撰写页 MUST 展示 `audio` / `video` 两个 tab 但置为不可用（标注"即将支持"）。提交 `contentType != text` 的祝福 MUST 被拒绝。

#### Scenario: P1 选择语音形式

- **WHEN** 用户尝试提交一条 `contentType = audio` 的祝福
- **THEN** 系统拒绝并提示"语音 / 视频祝福即将支持，先用文字写一段"

#### Scenario: 形式 tab 可见但不可用

- **WHEN** 用户进入撰写页
- **THEN** 看到「文字 / 语音 / 视频」三个 tab，「文字」选中，另两个灰置并标注"即将支持"

### Requirement: 发送者信息来自画像

祝福不再单独填写"给谁 / 落款 / 城市"。收件人由受众筛选决定（见 `blessing-audience`）；收件人看到的发送者信息（昵称 / 落款、城市、大致距离）取自发送者的个人画像（见 `user-profile`），在读取时现算。祝福正文与画像 MUST 分开存储。

#### Scenario: 收件人看到的发送者信息

- **WHEN** 收件人在收件箱查看一条祝福
- **THEN** 显示发送者的昵称 / 落款、城市、四舍五入到公里的距离，不显示精确位置或 openid

### Requirement: 静心与发心引导

撰写页 SHALL 提供不打扰的引导：不必赶的文案、可选的呼吸 / 停顿动效，以及一句帮助"发心"的具体提示（大意："想一想 TA 打开这段话时，正处在什么心情"），不是空泛的鸡汤。系统 MUST NOT 对撰写过程计时或评分。

#### Scenario: 撰写页无计时评分

- **WHEN** 用户在撰写页停留任意时长
- **THEN** 系统不显示倒计时、不显示用心 / 质量分数

#### Scenario: 动笔前的发心提示

- **WHEN** 用户进入撰写页、正文还是空的
- **THEN** 页面展示一句具体的、引导用户设身处地为收件人着想的提示

### Requirement: 草稿保存与恢复

系统 SHALL 在用户主动保存、离开撰写页或会话过期时保存草稿。草稿 MUST NOT 对他人可见，MUST NOT 触发内容合规检查或生成分享卡片。重新进入创作时系统 SHALL 可恢复最近草稿。成功生成分享卡片后，对应草稿 MUST 被清理或标记为已发布。

#### Scenario: 会话过期后恢复草稿

- **WHEN** 用户撰写中会话过期，重新登录后进入创作
- **THEN** 系统恢复其最近一次草稿内容

#### Scenario: 草稿不进入审核

- **WHEN** 草稿被自动保存
- **THEN** 系统不对其调用内容合规检查、不生成任何公开链接
