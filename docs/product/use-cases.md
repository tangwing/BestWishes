# 用例设计

> 状态：v1，2026-09-04（按 [ADR 0004](../adr/0004-p1-stranger-broadcast-model.md) 重写为陌生人群发模型）。当前只覆盖 **P1**。
> 上游依据：[vision.md](vision.md)、[concept.md](concept.md)、[ADR 0004](../adr/0004-p1-stranger-broadcast-model.md)。
> 每个用例含触发者 / 前置 / 主流程 / 异常流 / 验收标准。验收标准写成可测断言，供 TDD 用。

---

## P1 范围

**做**：微信登录、**个人空间**（昵称 / 落款、城市、**经纬度位置**、性别、出生年、**标签**）、《用户内容与授权协议》、祝福范本（只作参考、不可一键套用）、撰写文本祝福（正文须自己录入、拦粘贴）、静心 / 发心引导、**受众筛选 + 预览**（距离 / 年龄 / 性别 / 标签，命中 ≤ 上限才可发）、**按条件群发**、自动内容合规检查（发布即校验 / 延迟送达）、**收件箱 + 站内通知**、**回一段祝福**（不能对话）、公开链接（传播用，访客免注册查看 + 举报）、发件箱管理、**回响**（原"坚持记录"）、审核队列。

**不做**（明确排除）：语音 / 视频祝福（`contentType` 留白，功能 P2）、AI 用心评估、祝福请求 / 匹配 / 推荐（移至 P2）、任何悬赏与资金、逆地理编码（经纬度→城市）、真实推送通道（P1 只有站内通知）、访客一键致意（移至 P4）、距离查询的空间索引。

## 参与者

| Actor | 说明 |
|---|---|
| **发送者** | 已登录、已设位置、已同意协议的用户，写祝福并群发 |
| **收件人** | 被某次群发命中的已登录用户，在收件箱收到祝福，可回一段祝福 |
| **访客** | 通过公开链接打开某条祝福的人，可未注册；可举报 |
| **平台** | 受众解析 + 人数上限、内容合规检查、投递扇出、通知、数据存储、回响 |
| **审核员** | 处理自动检查命中的人工复核队列、举报、申诉 |

## P1-UC-01 微信登录 / 注册

- **触发者**：访客点任何需要登录的入口。
- **主流程**：发起微信授权（openid / unionid，昵称头像可选）→ 首次登录建账户，记录来源 → 返回会话。
- **异常流**：拒绝昵称 / 头像仍可建号（占位名）；拒绝授权可浏览公开链接、不能创作。
- **验收**：
  - 同一 openid 多次登录只对应一个账户；回调重试幂等。
  - 未登录访客能看 `/p/:slug`，进 `/compose` 等被引导登录。

## P1-UC-02 完善个人画像

- **触发者**：登录后进入个人空间。
- **主流程**：设置昵称 / 落款、城市（显示用，只到城市级）、**经纬度**（浏览器 Geolocation 或手填）、性别、出生年、标签（从建议标签里选 + 可自定义）。
- **异常流**：浏览器不支持 / 拒绝定位 → 提示可手填经纬度。
- **验收**：
  - 位置（lat+lng 都有）齐备时 `canBroadcast=true`；缺任一为 `false`。
  - 画像用于**被别人的受众筛选命中**：只有设了经纬度的用户参与匹配。
  - 别人看到的只有城市和大致距离，看不到精确经纬度 / openid。

## P1-UC-03 同意《用户内容与授权协议》

- **主流程**：展示条款 → 逐项勾选（**群发 / 送达给符合条件的陌生人【必选】** / 精选展示【可选】/ 合成演绎【告知】）→ 记录版本 + 逐项留痕。
- **异常流**：不勾必选项 → 拦截，不放行创作。
- **验收**：
  - `GET /api/agreement/current` 返回 `alreadyConsented`；未同意时进 `/compose` 自动跳协议页，提交撞 `consent_required` 也跳。
  - 协议改版（版本号变）→ 下次创作要重新确认。

## P1-UC-04 参考范本 / 自由创作

- **验收**：每类场景 ≥3 条范本；范本**只作参考**——没有"一键填入"按钮，示例文字不可选中；正文必须手动录入。加载失败回退纯自由创作。

## P1-UC-05 撰写一段文本祝福

- **主流程**：选形式（P1 只有「文字」可用，语音 / 视频灰置"即将支持"）→ 选场景 → 手写正文（呼吸动效 + 发心提示，`prefers-reduced-motion` 关动效）。
- **异常流**：往正文粘贴 → 拦截 + 温和提示；正文过短 / 过长 → 提交被拒。
- **验收**：
  - `contentType != 'text'` 的提交被拒（"语音 / 视频祝福即将支持"）。
  - 正文字数在 `[bodyMinLen, bodyMaxLen]`（默认 15–500）。
  - 无计时、无评分。

## P1-UC-06 保存草稿

- **验收**：草稿自动保存（正文 + 场景 + 受众筛选）；不触发审核、不群发；可恢复；成功群发后清理。仅本人可见。

## P1-UC-07 选择受众并预览命中人数

- **前置**：发送者已设位置。
- **主流程**：设距离半径（以自己位置为圆心）+ 年龄区间 + 性别 + 标签（命中任一）→ 点「预览收件人」→ 返回命中总数 + 上限 + 距离最近的前若干位（昵称 / 城市 / 距离 / 年龄）。
- **异常流**：未设位置 → `location_required`。
- **验收**：
  - 预览不含发送者自己、不含没有位置的人、不含范围外的人。
  - `canSend = 命中数 ∈ [1, maxAudienceSize]`。

## P1-UC-08 按条件群发祝福

- **主流程**：预览通过后点「发送」→ 平台**定格**收件人列表（快照）→ 祝福进 `verifying` + hold → 内容校验通过后逐个投递到收件箱 + 发通知。
- **异常流**：
  - 命中 0 人 → `audience_empty`。
  - 命中 > `maxAudienceSize`（默认 10）→ `audience_too_large`，提示当前人数与上限。
  - 缺协议 → `consent_required`；缺位置 → `location_required`。
- **验收**：
  - 提交返回 `recipientCount`。
  - 投递在祝福**首次进入 `published`** 时发生，幂等（`deliveredAt`）——申诉恢复不重复投递。
  - 提交后加入 / 退出范围的人不影响已定格的收件人列表。

## P1-UC-09 自动内容合规检查

- **主流程**：提交即"已发送"，接收方可见性 hold 住；规则审核（可插拔 `ModerationProvider`）出三档：
  - **pass** → hold 到点由扫描任务发布 → 投递。
  - **suspect** → 保持 `verifying` + 进人工队列，不投递。
  - **violation** → `rejected`，不投递。
  - **provider 不可用** → 保守：维持 hold + 进队列。
- **审核目标**（P1）：过滤无效 / 垃圾 / 违规。刷屏 / 空 / 乱码 → violation；站外导流（链接 / 联系方式）/ 拉客敛财话术 → suspect；违法违禁词 → violation。不评判"写得好不好"。
- **验收**：留痕（档位、命中大类、hold 时长、事件写 `blessing_events` 子表）；hold 超时打升级标记。

## P1-UC-10 收件箱

- **主流程**：收件人打开收件箱 → 按投递时间倒序列出收到的祝福，每条显示发送者昵称 + 城市 + 大致距离 + 正文（或占位）。收件箱每 3 秒自动刷新；打开即把未读通知 / 未读收件标记为已读。
- **验收**：
  - 只列 `published` 且未过期的祝福正文；发送者撤回 / 删除 / 平台下架 / 链接过期后显示中性占位、不返回正文。
  - 不暴露发送者精确位置 / openid。

## P1-UC-11 站内通知

- **主流程**：命中的祝福投递时给收件人建一条 `blessing_received` 通知。顶栏收件箱入口显示未读徽标（每 4 秒轮询）。
- **验收**：`GET /api/notifications` 返回列表 + `unread`；打开收件箱后 `unread → 0`。P1 无真实推送通道。

## P1-UC-12 回一段祝福

- **主流程**：收件人对一条收到的祝福点「回一段祝福」→ 撰写页 `scope=reply`，受众恒为对方一人，无受众筛选 → 同样过内容校验 → 进对方收件箱。
- **异常流**：不能回复自己；回复对象不存在 → `not_found`。
- **验收**：没有会话线程、没有聊天；回信是一条独立的祝福，走完整状态机。

## P1-UC-13 发件箱

- **验收**：列出自己群发 / 回复出去的祝福 + 状态 + 收件人数 / "回复"标签。撤回即时可逆；`verifying` 期可取消（清待发布 + 关联工单）；`withdrawn` 可重新发布（重走校验）；到期可续期（不重走校验、不加计数）；删除二次确认 + 不可逆 + 不在列表。撤回 / 删除 / 下架回撤回响计数，**链接过期不回撤**。

## P1-UC-14 公开链接 + 访客查看

- **主流程**：每条祝福有 `/p/:slug` 公开页，用途是"转发出去带更多人来平台"，**不是送达机制**。访客免注册打开，按状态渲染正文 / 中性占位。
- **验收**：接口对非公开可见的祝福只返回占位枚举、绝不返回正文；不暴露 openid / 精确位置。

## P1-UC-15 举报一条祝福

- **验收**：访客可匿名提交（IP+UA 或长期 cookie 指纹）；同源重复举报合并计数；高危大类（illegal / offensive）即时临时下架等人工复核；举报人不获知作者身份。

## P1-UC-16 审核员处理队列

- **验收**：队列按优先级（高危举报 90 > 举报 60 > 自动疑似 30）；复核动作（通过 / 下架 / 要求修改）驱动祝福状态机 + 留痕 + 每工单有终态；`verifying` 期通过 → 投递；`taken_down` 通过 → 申诉恢复（不重复投递）。P1 不做角色鉴权（任意会话可进审核台）。

## P1-UC-17 查看回响

- **验收**：按发送者所在地区自然日聚合"进入 `published` 且有效"的祝福数；仅本人可见；无排行、无积分、无等级；连续天数只作轻描述。跨时区正确切自然日。
