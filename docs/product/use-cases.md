> 每个用例含：触发者 / 前置条件 / 主流程 / 异常流 / 验收标准。验收标准写成可测断言，供后续 TDD 用。

## P1 范围回顾

做：微信登录、**个人空间**（预设落款 / 城市 / 偏好）、《用户内容与授权协议》、祝福范本库（**只作参考、不可一键套用**）、撰写文本祝福（**正文须自己录入、拦粘贴**；三项发送者信息）、静心与"发心"引导、自动内容合规检查、发布即校验 / 延迟送达、生成可分享卡片、微信分享、访客免注册查看、**收发记录**（发件箱完整 / 收件箱空状态）、坚持记录、举报、审核队列。

**不做**（明确排除）：音视频、AI 用心评估、祝福请求 / 匹配 / 推荐、任何悬赏与资金、站内 user→user 定向送达（收件箱在 P1 为空）、合成视频、iOS / Android 原生端、定位自动获取城市（P1 占位）、访客一键致意（移至 P4）。

## 参与者（Actors）

| Actor | 说明 |
|---|---|
| **作者**（Author） | 已登录用户，撰写并分享祝福 |
| **访客**（Visitor） | 通过分享链接打开祝福卡片的人，可未注册、无微信授权 |
| **平台**（System） | 内容合规检查、卡片渲染、数据存储、坚持记录 |
| **审核员**（Moderator） | 处理自动检查命中的人工复核队列、举报 |

## P1-UC-01 微信登录 / 注册

- **触发者**：访客点击"写一段祝福"或任何需要登录的入口。
- **前置条件**：在微信生态内（小程序 / 微信内网页）。
- **主流程**：
  1. 用户点击登录。
  2. 平台发起微信授权（获取 openid / unionid，昵称、头像为可选授权）。
  3. 首次登录：创建用户，记录注册来源、默认地区（可由用户后续修改）。
  4. 返回登录态（会话令牌）。
- **异常流**：
  - 用户拒绝授权 → 允许以受限态浏览已分享卡片，但不能创作；给出说明。
  - unionid 缺失（未开放平台绑定）→ 以 openid 为账户主键，记录待补。
  - 网络失败 → 可重试，不产生重复账户（以 openid 幂等）。
- **验收标准**：
  - 同一微信用户多次登录只对应一个账户。
  - 拒绝头像 / 昵称授权时，账户仍可创建，展示用默认头像与占位名。
  - 未登录访客能打开分享卡片（见 UC-09），不能进入创作页。

## P1-UC-02 同意《用户内容与授权协议》

- **触发者**：用户首次进入创作流程，或协议版本更新后首次创作。
- **前置条件**：已登录。
- **主流程**：
  1. 展示协议要点：著作权归用户；平台获非独占、全球、免费、可转授权许可；用途**分层勾选**——
     - 送达 / 展示给被分享人：**必选**（不同意则无法生成分享卡片）。
     - 平台精选展示与产品宣传：**默认勾选（开启）**，用户可取消。
     - 未来合成 / 演绎（音视频阶段）：**可选**，仅告知，P1 不触发。
  2. 记录同意的协议版本号、时间、勾选项。
- **异常流**：
  - 用户不同意"必选"项 → 不能继续创作，返回首页。
  - 协议改版 → 下次创作前需重新确认变更项。
- **验收标准**：
  - 每次同意留痕（用户 ID、协议版本、时间戳、逐项选择）。
  - "精选展示"默认开启，但取消开关必须清晰可见、可随时在设置或祝福详情里改。
  - "精选展示"被取消的祝福，不出现在任何平台公开栏目 / 宣传物料中；已收录的需在约定时限内撤下。
  - 撤回同意的处理见 UC-11 与 concept 待澄清项。
- **合规备注**：PIPL 及个人信息保护规范不鼓励"非必要授权默认勾选"。"精选展示"默认开启需法务确认；若不合规，退化为"发布后一步式询问是否愿意被精选"（opt-in，入口显眼）。见开放问题 2 / ADR-M。

## P1-UC-03 参考范本 / 选择自由创作

- **触发者**：已登录用户进入创作页。
- **前置条件**：已同意协议（UC-02）。
- **主流程**：
  1. 平台按场景（生日、节日、鼓励、康复祈愿、纪念 / 追思、日常问候）展示范本，每条含起草提示 + 示例文字。
  2. 范本**只作参考**——没有"用这个"之类把示例填进正文的按钮；示例文字设 `user-select: none`，减少顺手复制。
  3. 用户看着范本，在独立的正文框里自己写；或直接自由创作。
- **异常流**：
  - 范本库加载失败 → 允许直接自由创作。
- **验收标准**：
  - 范本由运营后台维护，含**护栏词校验**：不得出现"宗教服务 / 代祷收费 / 超度 / 消灾解厄"等触发支付合规风险的表述（命中则拒绝发布）。
  - 范本至少覆盖 6 类场景，每类 ≥3 条。
  - 界面上没有任何把范本一键填入正文的操作。

## P1-UC-04 撰写一段静心祝福（自己录入 + 三项发送者信息）

- **触发者**：用户在撰写页。
- **前置条件**：UC-03。
- **主流程**：
  1. **祝福正文**：多行文本，**必须自己录入**——粘贴进正文被拦截，给温和提示（"用你自己的话写出来，TA 会感受到不一样"）。字数下限 / 上限可配置（建议 15–500）。
  2. **发送者信息**（三项）：给谁（称呼，必填、每次填）；落款（"我是谁"，默认取个人空间、可当场改）；城市 / 地区（默认取个人空间、可当场改，粒度不超过城市 / 省级）。**不再有**关系、开头 / 落款自由文本——这些直接写进正文。
  3. **静心 + 发心引导**：不打扰的引导——"不必赶"的文案、可选呼吸 / 停顿动效，以及一句具体的发心提示（"想一想 TA 打开这段话时，正处在什么心情"），不是空泛鸡汤。不计时、不评分。
  4. 点击"完成" → 进入 UC-06。
- **异常流**：
  - 正文为空 / 越界 / 缺"给谁" → 阻止提交并提示。
  - 粘贴进正文 → 拦截 + 温和提示，用户继续打字。
  - 会话过期 → 见 UC-05。
- **验收标准**：
  - "给谁"和"正文"必填；落款、城市可空。
  - 粘贴文本进正文不会被接受；语音输入 / 输入法候选正常。
  - 落款、城市的默认值来自个人空间（UC-15）；当场修改只影响这一条。
  - 城市只到城市 / 省级，不采集精确位置。
  - 三项发送者信息与正文分开存储。

## P1-UC-05 保存草稿

- **触发者**：用户主动保存，或离开撰写页 / 会话过期时自动保存。
- **前置条件**：撰写页有内容。
- **主流程**：草稿按用户 + 时间保存；重新进入创作可恢复最近草稿。
- **异常流**：多设备并发编辑 → 以最后保存为准，提示存在较新草稿。
- **验收标准**：
  - 自动保存不触发合规检查、不生成卡片。
  - 草稿不对任何他人可见。
  - 生成卡片成功后，对应草稿被清理或标记为已发布。

## P1-UC-06 自动内容合规检查

- **触发者**：用户在撰写页点击"完成"。
- **前置条件**：正文通过基本校验（UC-04）。
- **主流程**：
  1. 平台调用内容审核（涉政 / 色情 / 仇恨 / 诈骗 / 违法违规 / 敏感）对正文 + 个性化字段做检测。
  2. **「发布即校验、延迟送达」模型**——作者点击"完成"后立即视为"已发送"（作者侧看到成功、拿到链接、可分享），但平台 hold 住**接收方可见性**，先跑校验：
     - **自动通过**（目标数分钟内）→ 祝福转"已发布"，接收方可见（UC-09）。
     - **疑似 / 低置信** → 继续 hold，转人工复核队列（UC-14）；作者侧提示"审核中，对方稍后可见"。
     - **明确违规** → 不放行，祝福转"已驳回"；作者侧提示大类原因 + 修改 / 申诉入口；链接对访客显示中性占位。
- **异常流**：
  - 审核服务超时 / 不可用 → 保守策略：维持 hold + 进人工队列，绝不"默认放行"。
  - 用户对驳回结果申诉 → 生成申诉工单，进入 UC-14。
  - hold 超过约定上限（如 24h）仍未有结论 → 升级 + 通知作者当前状态。
- **验收标准**：
  - 任何对访客可见的祝福，都至少经过一次自动检查且结果非"明确违规"。
  - 作者侧"已发送"与接收方侧"可见"是两个独立状态；校验期间访客访问链接看到的是"祝福正在准备中"占位，不是正文。
  - 驳回时不展示可被规避的具体命中词，只给大类。
  - 检查结果（档位、供应商、时间、命中大类、hold 时长）留痕，可追溯。
  - **无 AI 用心 / 质量评分**——本用例只做安全合规，不做好坏评判。

## P1-UC-07 生成可分享的祝福卡片 / 页面

- **触发者**：UC-06 未判"明确违规"（即"自动通过"或"疑似待复核"）。
- **前置条件**：已同意协议"送达"必选项。
- **主流程**：
  1. 平台渲染一个祝福卡片 / 落地页：正文、来自"[城市] 的 [昵称]"、给"[称呼]"、场景、时间；视觉上安静、克制。
  2. 生成一个**公开可访问的短链 / 页面**（接收方无需登录）。链接立即可分享；页面内容按 UC-06 的可见性状态渲染（准备中 / 已发布）。
  3. 生成分享用的标题、缩略图。
  4. 记录该祝福状态（校验中 / 已发布），归入作者的祝福列表；**坚持记录在"已发布"时才 +1**。
  5. 设置链接**有效期**（默认值待定，建议 90–180 天），到期转 UC-09 的"已过期"态；作者可在有效期内续期。
- **异常流**：
  - 渲染 / 短链服务失败 → 祝福保存为"待生成"，可重试；不丢失内容。
- **验收标准**：
  - 卡片页在未登录、非微信环境下也能打开（分享外链兜底）；"已发布"时展示正文，其他状态展示对应占位。
  - 页面不暴露作者的 openid、精确位置、手机号等隐私。
  - 若作者取消了"精选展示"，页面不得带任何"可能被平台收录 / 推广"的标识或行为。
  - 页面按需带"内容由用户创作"说明；不含 AI 生成标识（P1 无 AI 生成内容）。

## P1-UC-08 通过微信分享祝福

- **触发者**：作者在卡片生成后点击"分享"。
- **前置条件**：UC-07 完成。
- **主流程**：
  1. 调起微信分享（分享给好友 / 群 / 朋友圈，具体渠道以平台策略与合规为准）。
  2. 分享卡片展示标题 + 缩略图 + 短描述。
  3. 作者也可复制外链在微信外分享。
- **异常流**：
  - 分享组件不可用（非微信环境）→ 提供复制链接兜底。
- **验收标准**：
  - 被分享人点击后直达 UC-09 的查看页，无需注册 / 授权。
  - 同一祝福多次分享指向同一稳定链接。
  - 作者可在祝福详情看到"是否已生成链接"，P1 不统计打开数（可留待 P4「看见善意」）。

## P1-UC-09 访客打开祝福卡片查看

- **触发者**：访客点击分享卡片 / 外链。
- **前置条件**：链接存在。
- **主流程**：
  1. 按祝福状态渲染：
     - **已发布** → 展示正文、来源（城市 + 昵称）、场景、时间。
     - **校验中** → "这份祝福正在准备中，稍后再来看看"占位页。
  2. 提供轻量入口："我也写一段祝福"（引导注册，非强制）。
- **异常流**：
  - 祝福已被作者撤回 / 删除 → "这份祝福已被收回"的友好占位页，不报错、不泄露原内容。
  - 祝福因举报 / 复核被下架、或被判"明确违规" → 中性占位页。
  - 链接**已过期** → "这份祝福的分享期限已过"占位页，提示"如果你保存过图片仍可留作纪念"；引导作者续期（若访客恰为作者本人）。
  - 链接无效 / 拼写错误 → 通用 404 占位页。
- **验收标准**：
  - 查看页不设登录墙。
  - 撤回 / 过期 / 下架后 60 秒内，公开页不再返回原文（缓存失效策略需覆盖）。
  - 页面不采集访客除必要访问日志外的个人信息。
  - 各占位页文案中性、不泄露原内容、不报技术错误。

## P1-UC-10 访客一键致意（可选）

> **不进 P1**（2026-09-01 决定）。理由：闭环价值有，但会引入匿名写入面与防刷需求。移到 P4「看见善意」一并做。以下为存档描述。

- **触发者**：访客在查看页点击"合十 / 收到 / 谢谢"。
- **前置条件**：祝福处于已发布。
- **主流程**：记录一次匿名致意（去标识：仅计数 + 粗粒度地区，可选）；作者可在祝福详情看到"有人收到了你的祝福"。
- **异常流**：同一访客短时间重复点击 → 去重 / 限频。
- **验收标准**：
  - 不需要访客登录。
  - 不记录可定位到个人的标识。
  - 作者侧只看到聚合信息（次数 / 大致来源），看不到个人。

## P1-UC-11 收发记录（发件箱管理 / 收件箱空状态）

- **触发者**：用户进入"收发记录"。
- **前置条件**：已登录。
- **主流程**：
  1. 两个视图切换：**发件箱**（送出的）、**收件箱**（收到的）。默认发件箱。
  2. **发件箱**：列出自己创作过的祝福（时间、场景、给谁、状态）。对每条可：
     - **撤回 / 取消**：`published` 撤回、`verifying` 取消——立即停止公开访问（UC-09 转占位页），保留数据；`verifying` 取消同时清除待发布定时。
     - **删除**：撤回 + 请求删除内容；按 PIPL——技术上难以彻底物理删除时至少停止"存储与安全外的一切处理"（冻结）。
     - **续期**：对将过期 / 已过期的祝福延长有效期。
     - **重新发布**：撤回后可重新发布，重新走校验。
  3. **收件箱**：P1 阶段站内没有 user→user 送达 → 展示友好空状态（"你写给别人的祝福通过链接送达；站内收发要等主动赠送和祝福请求上线"），入口和 tab 不隐藏。
- **异常流**：
  - 对已分享的祝福执行删除 → 已分发链接失效，已交付的截图 / 转发无法追回（协议已事先告知）。
- **验收标准**：
  - 撤回是即时、可逆；`verifying` 也可取消；删除按不可逆处理并二次确认；操作留痕。
  - 删除后不再出现在发件箱。
  - **撤回 / 删除 / 下架回撤坚持记录计数；链接过期不回撤。**
  - 收件箱可访问、显示说明性空状态，不报错。

## P1-UC-12 查看坚持记录

- **触发者**：作者进入个人页。
- **前置条件**：已登录。
- **主流程**：展示累计写了多少段祝福、连续天数、最近活跃；措辞温和，不做排行、不做 KPI 式激励。统计"曾发布且未被作者撤回 / 平台下架"的祝福——**链接过期不影响计数**。
- **异常流**：
  - 跨时区导致"连续天数"边界模糊 → 以用户所在地区自然日为准。
  - 撤回 / 删除 / 下架导致某自然日创作数归零 → 连续天数在该日中断，按新数据重算。
- **验收标准**：
  - 记录仅对作者本人可见。
  - 计数与"已发布且有效"的祝福集合始终一致（撤回 / 删除即时反映）。
  - 不将坚持记录转化为积分 / 等级 / 可变现物（反商业化护栏）。

## P1-UC-13 举报一条祝福

- **触发者**：访客或登录用户在查看页点击"举报"。
- **前置条件**：祝福处于已发布。
- **主流程**：
  1. 选择举报大类（不实信息 / 冒犯内容 / 骚扰 / 涉嫌违法 / 其他）+ 可选补充说明。
  2. 生成举报工单，进入 UC-14 队列。
  3. 高危大类（涉嫌违法 / 严重冒犯）触发**立即临时下架**待人工复核。
- **异常流**：
  - 同一人对同一祝福重复举报 → 合并计数，不重复建单。
  - 恶意批量举报 → 限频；举报准确率纳入举报人信誉（后续阶段）。
- **验收标准**：
  - 举报不需要登录（至少匿名可提交），但记录必要的防滥用信息。
  - 高危举报后，公开页在约定时限内转占位页。
  - 举报人不获知被举报作者的身份信息。

## P1-UC-14 审核员处理复核 / 举报队列

- **触发者**：自动检查产出"疑似"、或收到举报、或收到用户申诉。
- **前置条件**：审核员已在运营后台登录并具备权限。
- **主流程**：
  1. 队列按优先级排序（高危举报 > 用户申诉 > 疑似内容 > 随机抽检）。
  2. 审核员查看内容与上下文，作出：通过 / 下架 / 要求修改。
  3. 结果通知作者（下架 / 驳回附大类原因与再申诉入口）。
  4. 随机抽检已通过内容，用于校准自动检查阈值。
- **异常流**：
  - 审核员之间判定不一致 → 升级资深二审。
  - 申诉二次被驳回 → 关闭工单并告知最终结果。
- **验收标准**：
  - 每个进入队列的条目都有终态（通过 / 下架 / 修改）与处理人、时间、理由留痕。
  - 下架 / 恢复对公开页的生效时限有明确 SLA（数值待定）。
  - 抽检覆盖率可配置且被记录。

## P1-UC-15 个人空间

- **触发者**：用户进入"个人空间"。
- **前置条件**：已登录。
- **主流程**：
  1. **预设落款**（"我是谁"，默认昵称）和**城市 / 地区**（手填，粒度到城市 / 省级）。撰写祝福时这两项作默认值。
  2. **定位授权开关**：切换"用定位自动获取城市"。P1 只存这个选择，不实际调用定位（占位，注明未上线）。
  3. **精选展示默认偏好**：设置自己创作时《授权协议》里"精选展示"的默认勾选状态。个人偏好优先于系统默认。
  4. **坚持记录入口**：跳转 UC-12。
  5. **退出登录**；**发起注销**（P1 可先走人工 / 占位流程）。
- **异常流**：
  - 城市填写超过城市 / 省级粒度 → 系统只接受到该粒度。
- **验收标准**：
  - 落款、城市设置后，撰写页默认值取自这里（UC-04）。
  - 定位开关状态留痕；P1 下打开也不改变"城市需手填"。
  - 精选展示个人偏好设置后，之后创作的授权项默认勾选状态跟随它。
  - 退出后回到未登录首页。

## P1 关键数据对象（初步，供架构阶段细化）

- **用户**：openid / unionid、昵称、头像、注册来源。
- **个人空间**：用户、落款、城市 / 地区、定位授权开关、精选展示个人默认偏好。
- **祝福草稿**：作者、正文、发送者信息、更新时间。
- **祝福**：作者、正文、发送者信息（给谁 / 落款 / 城市，与正文分开存）、场景、状态（校验中 / 已发布 / 已驳回 / 已撤回 / 已删除 / 已下架 / 已过期）、公开链接、链接有效期与续期记录、合规检查记录（含 hold 时长）、创建时间、发布时间。
- **协议同意记录**：用户、协议版本、逐项勾选（含精选展示）、时间戳。
- **收件箱条目**（P1 只留结构，不填充）：接收用户、送出用户、关联祝福、送达时间。
- **举报 / 复核工单**：目标祝福、来源（举报 / 自动 / 申诉）、大类、状态、处理人、理由、时间线。
- **坚持记录**：用户、按日聚合的"曾发布且未被作者撤回 / 平台下架"的创作次数（链接过期不回撤）。

### 已拍板

- **发布模型**（09-01）：作者侧"先发布"（即时成功、拿到链接），平台 hold 数分钟做校验，通过后接收方才可见——"发布即校验、延迟送达"。
- **精选展示**（09-01）：默认开启，可取消（合规待法务确认，见下）。
- **访客致意（UC-10）**（09-01）：不进 P1，移到 P4。
- **祝福链接**（09-01）：设有效期（默认值待定，建议 90–180 天），作者可续期。
- **坚持记录回撤**（09-02）：撤回 / 删除 / 下架回撤计数；**链接过期不回撤**（人那天确实写了）；续期不加计数。
- **校验期取消**（09-02）：作者可在 `verifying` 期间取消（`verifying → withdrawn`），清除待发布定时。

### 仍待拍板

1. **"精选展示"默认开启的合规性**：需法务确认是否违反 PIPL"非必要授权不得默认勾选"；不行则退化为发布后 opt-in（入口显眼）。→ ADR-M。
2. **hold 时长目标与上限**：自动通过的目标时延、疑似进人工后的最长 hold。
3. **链接有效期默认值**、到期前提醒机制、"过期后作者侧是否仍可查看/导出"。
4. **字数上下限、范本分类与条目的最终清单**。
5. **技术选型**：见 [ADR 0003](../adr/0003-p1-tech-stack-web-first.md) 的决策项表。

### 「祝福链接不设长期公开」的风险与缓解

- **风险**：祝福是情感资产，追思 / 婚礼 / 重要节日场景，接收方过一段时间想回看却发现链接失效 → 负面体验；也可能被解读为"平台把我的祝福弄没了"。
- **缓解**：
  - 有效期内允许接收方**保存卡片图片**留作纪念（不依赖链接存活）。
  - 到期**不删除数据**，只是公开页转"已过期"占位；作者可随时续期恢复。
  - 到期前对作者推送提醒（若有通知渠道）。
  - 追思 / 纪念这类"希望长期保存"的需求，留到 P4 做"永久纪念页 / 接收方领取到账户"。
- **收益**：减少长期公开内容的审核与合规敞口，符合数据最小化；也给未来的"纪念"增值功能留了空间。
