# 产品概念

> 状态：v4，2026-09-01 更新。理念与定位见 [vision.md](vision.md)；后端能力分解见 [capabilities.md](capabilities.md)；合规与技术调研见 [../research/2026-09-01-funds-ai-licensing.md](../research/2026-09-01-funds-ai-licensing.md)。仍有开放问题，见文末与 [AGENTS.md](../../AGENTS.md) §6。

## 一句话

一个练习专注、传递善意的多端平台——让人们用心地互相发布、悬赏、赠送「祝福」。

## 核心场景

1. **静心祝福（陌生人群发）**：用户静下心来，写 / 录一段祝福，选一个**受众范围**（以自己位置为圆心的距离 + 年龄 / 性别 / 标签），把它群发给范围内的陌生人。命中人数有上限，超过要缩小范围。命中的人在**收件箱**收到 + 收到**通知**。首发只做**文本**，音视频与 AI 用心反馈随后引入。
2. **回一段祝福**：收件人对一条收到的祝福，只能回一段祝福（同样过校验，进对方收件箱）。**没有聊天、没有会话**——善意是一来一回的祝福，不是对话。
3. **看见善意 / 传播**：每条祝福有一个公开链接，可转发到微信，带更多人来平台给陌生人写祝福。
4. **发布祝福请求 + 响应请求**（P2）：用户发布「希望收到的祝福」，任何人可无偿响应或领取悬赏。
5. **悬赏与分账**（P3）：请求方设悬赏池，平台按评分比例放款。
6. **看见善意进阶**（P4）：来源地图、贡献者与他们做的事。
7. **一键合成**（P5）：把多条祝福视频合成一段，用于婚礼、纪念等场合播放。

## 定位说明

对外是「静心 + 善意表达」的空间，挂靠正念 / 觉察 / 冥想，**不做宗教定位**。宗教场景（诵经回向、代祷等）只是承载的众多情境之一。详见 [vision.md](vision.md) 的「定位」一节。支付合规侧也印证了这一点：微信支付治理"借宗教敛财"类商户，商户经营范围与应用类目必须是"正念 / 静心 / 祝福"。

## 首发切入点（Beachhead）

选择一个小众但高契合的群体跑通闭环：**华人佛教群体**（中国大陆 + 全球华人佛教徒）——作为冷启动的**楔子**，不是产品对外身份。

- 支付习惯明确：微信支付 / 支付宝。
- 需求真实：他们希望把为他人 / 逝者的祈福做得更专注、更圆满。
- 传播路径顺：微信 / 小程序分享，冷启动成本低。

后续以普世的「祝福 / 静心」框架向更广人群与全球化场景扩展。

## 能力上线顺序（Rollout）

1. **陌生人祝福（P1）**：注册用户有画像（位置 / 性别 / 年龄 / 标签）→ **文本祝福** + **按条件群发**给附近陌生人（人数上限约束）→ 收件人在**收件箱**收到 + 通知 → 只能**回一段祝福**。附《用户内容与授权协议》框架。**无 AI 评估、无悬赏、无任何资金功能。** 见 [ADR 0004](../adr/0004-p1-stranger-broadcast-model.md)。
2. **音视频 + AI 用心反馈（P2）**：录制音 / 视频；转写对齐；完整性 / 中断 / 专注度 / 流畅度反馈；真人校验。同时引入**祝福请求 + 匹配**（兴趣标签个性化推荐 + 类别内悬赏排行榜 + 标签外探索性推荐）。
3. **悬赏与分账（P3）**：悬赏池、充值、按评分比例放款、祝福者钱包与提现。资金层由持牌机构托管（见下「已确定」）。
4. **精选与「看见善意」（P4）**：精选呈现、来源地图与贡献者事迹。
5. **合成与更多端（P5）**：一键合成祝福视频（含 AI 合成内容标识）；iOS / Android / Web 逐步推上。

## P1 范围（2026-09-04 按 [ADR 0004](../adr/0004-p1-stranger-broadcast-model.md) 重定）

- 形式：**仅文本**（`contentType` 给音视频留了字段和 UI 位，功能 P2）。
- 画像：注册用户设经纬度位置、性别、出生年、标签——用于被别人的受众筛选命中。
- 群发：写祝福 → 选受众（距离半径 + 年龄 + 性别 + 标签）→ 预览命中人数 → 命中 ≤ 上限（默认 10）才可群发。
- 收：命中的人在**站内收件箱**收到 + 收到通知；只能**回一段祝福**，不能对话。
- 公开链接：每条祝福有 `/p/:slug`，用于把祝福转发出去带人来平台——**不是送达机制**。
- 审核：过滤无效 / 垃圾 / 违规信息为主，不评"写得好不好"。
- **不含**：AI 评估（P2）、任何资金功能（P3）、祝福请求 / 匹配 / 推荐（P2）、语音视频、逆地理编码、真实推送。
- 上线《用户内容与授权协议》框架（用途分层：群发送达【必选】/ 精选展示【可选】/ 合成演绎【告知】）。

## 已确定（2026-09-01）

- **对外定位**：练习专注、传递善意的空间（正念 / 静心框架），非宗教工具。
- **首发人群**：华人佛教群体（作为楔子，见上）。
- **载体**：P1 仅文本，音视频从 P2 起。
- **P1 送达模型**（2026-09-04，[ADR 0004](../adr/0004-p1-stranger-broadcast-model.md)）：陌生人之间的**按条件群发**（距离 / 年龄 / 性别 / 标签 + 人数上限）→ 收件箱 + 通知 → 只能回祝福不能对话。原"祝福请求 / 匹配"整块移至 P2。
- **结算（P3 才启用）**：平台**只做账务层自托管**（记账、给赏规则、对账）；**资金层必须托管在持牌机构**——推荐 `我方账务系统` + `微信电商收付通 / 支付宝直付通`（祝福者作二级 / 特约商户，资金不进平台账户，抽成走分账佣金）。平台**绝不开设归集用户资金的自有账户**（二清红线）。
- **悬赏定性**：严格定性为"完成祝福行为的服务报酬 / 悬赏广告（民法典 499）"，**绝不做成"为受助人筹款"**（属公开募捐，初创无资格）。
- **社交模型**：以陌生人善意为主；无偿赠送是主体验，悬赏是特定场景助推器。
- **评分与送达**：祝福始终送达；评分只影响给赏与"精选"，不给低分打负面标签。
- **AI 评估输出形态**（倾向）：多维标签（完整性 / 流畅度 / 专注度 / 个性化）+ 是否精选布尔 + 给赏比例，不对外暴露单一总分。
- **端**：后端能力先行；首发客户端候选为微信小程序，iOS / Android / Web 逐步推上。

## 仍待澄清

- 资金托管模式最终选型（收付通 / 直付通 vs 银行存管）及可接受的抽成率（受支付宝单笔分账 ≤30% 约束）。
- 公司主体与 ICP / EDI 资质、微信支付服务商资质的办理启动时点。
- AI 评分低于阈值时给赏比例的具体曲线；人工复核与申诉 SLA。
- 变现模式（悬赏抽成 / 增值功能 / 随喜供养），北极星指标的量化定义。
- 全球化节奏与向更广人群的扩展路径。
- 《授权协议》中"精选展示"默认开还是默认关。
