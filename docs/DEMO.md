## 模型一句话

**P1 · 群发**：你不认识 TA。选一个范围（"三公里内、25 岁以上的人"），把一段祝福群发过去。
命中人数不超过上限（默认 10）才允许发。收到的人在**收件箱**看到 + 收到**通知**，
只能"回一段祝福"，不能聊天。

**P2 · 祝福请求**：反过来——你写下自己的处境（"最近考研压力很大"），可选附一段稿子，
发布到**请求广场**（未登录也能看）。愿意帮你的人可以照稿子念，也可以自己说，**录一段音频**
送回来，不是打字。音频经过一条打分管线（转写 → 安全审核 → 完整度 / 专注度 / 真诚度 → 挑战式
真人校验），回应人自己能看到多维反馈（从不是一个分数），你能在"我的请求"里听到所有回应。
视频形态还留了位，推到 P3。

## 走一遍：P1 群发（需要至少两个账号）

用两个浏览器（或一个正常窗口 + 一个无痕窗口）分别当**发送者**和**收件人**。

### 1. 收件人 A（无痕窗口）

| 步骤 | 看什么 |
|---|---|
| 登录 | 输昵称即可（占位登录）。 |
| 个人空间 → 位置 | 点「用浏览器定位」，或手填经纬度（如 `30.28` / `120.16`）。看到"位置已设置，可以群发"。 |
| 个人空间 → 性别 / 出生年 / 标签 | 选几个。这些是别人的受众筛选能命中的画像。 |

### 2. 发送者（正常窗口）

| 步骤 | 看什么 |
|---|---|
| 登录 → 个人空间 | 设位置（填一个离收件人几百米～几公里的坐标，如 `30.2741` / `120.1551`）。 |
| 同意协议 | 「群发 / 送达给符合条件的陌生人」必选。没同意直接进"写祝福"会被引导到这里。 |
| 写祝福 → 形式 | 「文字」高亮；「语音 / 视频」灰着标"即将支持"。 |
| 写祝福 → 正文 | 顶部呼吸圆环 + 发心提示。范本只作参考、选不中、**粘贴被拦**。 |
| 写祝福 → 送给谁 | 拖距离滑块、填年龄区间、选性别、选标签。点「预览收件人」→ 看到"将送达 N 人（上限 10）"和最近几位（昵称 · 城市 · 距离 · 年龄）。 |
| 发送 | 命中 0 或超过上限时按钮不可点。发出后到"已发送"页，显示"正在送往 N 位陌生人 · 校验中"。 |

### 3. 回到收件人 A

| 步骤 | 看什么 |
|---|---|
| 顶栏「收件箱」 | hold（8 秒）+ 扫描后出现红色未读徽标。 |
| 收件箱 | 看到祝福正文 + "来自 XX · 城市 · 约 N km 外"。收件箱每 3 秒自动刷新。 |
| 回一段祝福 | 点「回一段祝福」→ 撰写页顶部变成"回一段祝福给 XX"，没有受众筛选，只发给对方一人，同样过校验。 |

### 4. 发送者验收其余

| 在哪 | 看什么 |
|---|---|
| 收件箱 | 收到对方的回信。 |
| 「发出的」 | 群发记录 + 状态 + "群发 N 人" / "回复"标签；可撤回 / 删除 / 续期。撤回后收件人收件箱里那条变占位。 |
| 「回响」 | 送出祝福的累计数；"送人玫瑰手有余香"，无排行无积分。撤回 / 删除 / 下架即时回撤，链接过期不回撤。 |
| 「审核台」 | 命中护栏词的祝福停在这里，"通过"后才投递。举报的高危祝福排在最前（优先级 90）。 |
| 公开链接 | "已发送"页有 `/p/:slug`，用来把这条祝福转发出去带人来平台——不是送达机制。访客免登录可看、可举报。 |

## 试试这些内容（P1）

- 正常祝福（≥5 字）→ hold 后投递到收件箱。
- 含"超度收费" / "加我微信" → 判 suspect，停在校验中、进审核台，人工"通过"后才投递。
- 含"刷单返利" / 刷屏（"啊啊啊啊啊……"）→ 判 violation，直接"未通过"，不投递。
- 正文写"祝好"（太短）→ 提交被拒。

## 走一遍：P2 祝福请求 + 音频回应（需要至少两个账号）

浏览器要给麦克风权限（本机测试用真实麦克风；Chrome 也可以用
`--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` 启动参数免权限弹窗，
`e2e/playwright.config.ts` 就是这么配的）。

### 1. 求祝福的人 A

| 步骤 | 看什么 |
|---|---|
| 登录 → 个人空间 → 设位置 | 同 P1，匹配推送要用。 |
| 同意协议 | 同 P1，发布请求前必须同意过。 |
| 顶栏「祝福请求」→「发布一条请求」| 写处境（如"最近考研压力很大，希望有人鼓励我"），可选附一段稿子，可选标签。 |
| 发布 | 命中拉客护栏词（如"加我微信"）会**停在人工复核**，不进广场、不触发匹配，跟审核台通过后才公开——跟 P1 的祝福同一套护栏词表。 |

### 2. 回应者 B（另一个账号）

| 步骤 | 看什么 |
|---|---|
| 登录 → 个人空间 → 设位置 + 打几个标签 | 标签跟请求的标签重合，会收到匹配通知（顶栏「祝福请求」旁的未读徽标）。 |
| 广场（顶栏「祝福请求」，未登录也能看） | 看到 A 发的请求。点「录一段祝福回应」。 |
| 回应页 | 看到 A 的处境 + 稿子（如果有）+ 一个**验证码**（如 `372`）；下面是录音组件——点「开始录音」看波形跳动，说话时说出验证码，点「结束录音」。P2 不接真实语音识别，在下面文本框里手动写一下刚才说了什么（记得带上验证码）。 |
| 提交 | 跳到反馈页：完整度 / 专注度 / 真诚度三个标签（不是分数），命中疑似或没听清验证码时会提示"转人工复核"。 |

### 3. 回到 A

| 在哪 | 看什么 |
|---|---|
| 「我的请求」→「查看回应」 | 打分完成、hold 结束后（demo 里几秒钟）看到 B 的回应，能直接播放。可以撤回请求（撤回后广场看不到，也不能再回应——撤回是终态，同 P1 的祝福）。 |
| 「审核台」 | 命中护栏词的请求也会出现在这里（跟祝福共用一个队列），标"祝福请求"，通过后才公开 + 触发匹配推送。 |

## 环境变量

P1：`BW_HOLD_SECONDS`、`BW_MAX_AUDIENCE`（群发人数上限）、`BW_AUDIENCE_MAX_RADIUS_KM`、`BW_BODY_MIN_LEN` / `BW_BODY_MAX_LEN`、`BW_LINK_TTL_DAYS`、`BW_DB`（`memory` / `pglite`）、`BW_PGDATA`。
P2：`BW_AUDIO_MIN_DURATION_SEC` / `BW_AUDIO_MAX_DURATION_SEC`（录音时长上下限）、`BW_AUDIO_DIR`（本机音频落盘目录）、`BW_LIVENESS_SECRET`（挑战式真人校验的签名密钥，生产环境务必换成真随机值）。
都见 `server/src/config/app-config.ts` / `server/src/config/env.ts`。

## 这版没有的（见 BACKLOG）

真实微信授权、真实内容安全 API、真实语音识别（P2 靠回应者自己补充文字）、逆地理编码（经纬度 → 城市）、真实推送通道、视频祝福（推到 P3）、悬赏与资金（P3）、i18n 抽取、PWA。审核台任何登录用户都能进（`add-moderation-rbac` 已出 spec，等评审后落地）。
