# P1 初版 Demo 走查

> 2026-09-02。P1「文本静心祝福」的可运行 Demo。技术栈见 [ADR 0003](adr/0003-p1-tech-stack-web-first.md)。
> 数据在内存里，重启清空。微信登录 / 内容审核 / PostgreSQL 都是占位或内存实现，见 [BACKLOG.md](../BACKLOG.md)。

## 起

```bash
pnpm install
pnpm demo        # 单进程，http://127.0.0.1:3000
# 或
pnpm dev         # 开发模式，client :5173
```

## 走一遍

| 步骤 | 看什么 |
|---|---|
| **登录** | 输昵称（占位登录，代替微信授权）。留空也能登。 |
| **个人空间** | 设"落款"和"城市"。定位开关是占位（P1 不实做）。"精选展示默认"是个人偏好。 |
| **同意协议** | "送达"必选；"精选展示"默认态跟随个人空间偏好。不勾"送达"会被拦。 |
| **写祝福** | 顶部呼吸圆环 + "想一想 TA 打开这段话时的心情"发心提示。范本**只作参考**，没有"用这个"按钮，示例文字选不中。**往正文里粘贴会被拦**，提示"用你自己的话写出来"。落款/城市默认取个人空间。 |
| **已发送** | "你的心意正在送往 阿明"。状态"审核中"。平台 hold 几秒（`BW_HOLD_SECONDS`，demo 默认 8s）跑内容校验。 |
| **访客落地页** `/p/:slug` | 校验期看到"祝福正在准备中"占位（不是正文）。几秒后自动刷新成正文卡片："来自 杭州 的 小林"。无登录墙。 |
| **坚持记录** | 发布后 +1。仅自己可见，无排行无积分。 |
| **收发记录** | "送出的"列出祝福 + 撤回/删除/续期。"收到的"是空状态（P1 站内没有 user→user 送达）。撤回后访客看到"已被收回"，坚持记录回撤。 |
| **举报**（访客页） | 选"涉嫌违法"→ 落地页立刻转占位，工单进审核台（优先级 90）。 |
| **审核台** | 队列按优先级。"通过"能把误报的祝福恢复；"下架"驱动状态机。每个动作留痕。 |

## 试试这些内容

- 正常祝福（≥15 字）→ hold 后正常送达。
- 含"超度收费" → 判 suspect，停在"准备中"，进审核队列，人工"通过"后才送达。
- 含"刷单返利" → 判 violation，直接"未通过"，访客看中性占位。
- 正文写"祝好"（太短）→ 提交被拒。

## 环境变量

`BW_HOLD_SECONDS`（送达 hold 秒数）、`BW_BODY_MIN_LEN` / `BW_BODY_MAX_LEN`、`BW_LINK_TTL_DAYS`、`BW_FEATURED_DEFAULT_ON` 等——见 `server/src/config/app-config.ts`。
