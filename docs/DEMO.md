# Demo 走查 — P1 陌生人群发 + P2 祈福广场/音频

> 2026-09-07。P1「陌生人祝福」+ P2 第一批「祝福请求 + 音频回应」的可运行 Demo。
> P1 模型见 [ADR 0004](adr/0004-p1-stranger-broadcast-model.md)，技术栈见 [ADR 0003](adr/0003-p1-tech-stack-web-first.md)；
> P2 这一批见 [openspec/changes/add-p2-wish-request-audio/](../openspec/changes/add-p2-wish-request-audio/)（design.md 有完整的打分管线设计）。
> 微信登录 / 内容审核 / 真实语音识别 都是占位或可切换实现，见 [BACKLOG.md](../BACKLOG.md)。

## 起

```bash
pnpm install
pnpm demo        # 单进程，http://127.0.0.1:3000（hold 8 秒，方便看"校验中"）
```

`pnpm demo` 现在用 PGlite 落盘到 `server/.pgdata`、音频落盘到 `server/.audio-data`，
**重启不丢数据**（个人资料、请求、录音都还在，登录态 30 天有效）。要干净重来：

```bash
pnpm demo:fresh  # 删掉 .pgdata / .audio-data 再起
```

**`pnpm demo` 恒 `BW_MODERATION=always_pass`：内容审核直接判 pass，不跑违禁词 /
护栏词判定**——开发节奏考虑，新功能还在快速迭代阶段，真实判定容易把测试内容
误挡、干扰的是功能验收而不是审核本身要验的东西。真实三档判定
（`RuleBasedProvider`）没删，只是demo默认不走它；要验证审核链路本身，加
`BW_MODERATION=rule_based` 覆盖：

```bash
BW_MODERATION=rule_based pnpm demo
```

纯内存（进程退出即清空，测试用；不传 `BW_MODERATION` 时默认 `rule_based`，
跟正式行为一致）：

```bash
pnpm --filter @bestwishes/client build
BW_HOLD_SECONDS=8 pnpm --filter @bestwishes/server start
```

## 模型一句话

**P1 · 群发**：你不认识 TA。选一个范围（"三公里内、25 岁以上的人"），把一段祝福群发过去。
命中人数不超过上限（默认 10）才允许发。收到的人在**我的福袋**看到 + 收到**通知**，
只能"回一段祝福"，不能聊天。

**P2 · 祈福广场**：反过来——你写下自己的处境（"最近考研压力很大"），可选附一段稿子，
发布到**祈福广场**（未登录也能看）。广场列表只给摘要 + "已收到 N 条回应"，回应内容**点进详情才看**——
把一条祈福当社区 Topic。愿意帮你的人可以照稿子念，也可以自己说，**录一段音频**送回来，不是打字。
音频经过一条打分管线（转写 → 安全审核 → 完整度 / 专注度 / 真诚度 → 挑战式真人校验），回应人自己
能看到多维反馈（从不是一个分数）。**收到回应不是就结束了**——请求人和回应者能就一条回应继续往返
回一段文字，详情页按时间正序显示成一条连续对话。视频形态还留了位，推到 P3；富文本 / 图片回复也还
没做（见 BACKLOG B-90）。

**首页（无需登录）**：不再是一句口号 + 一个「开始」按钮——首屏就是一条真实的、已公开的祈福 +
它最新一条回应的原文摘录（`redesign-kindness-entry`，2026-09）。访客能读处境全文、标签、全部文字
回应与往返回复；**音频回放要登录**，位置显示"登录后可收听"。登录只在真的要提交时（发一条祈福 /
回一段祝福 / 群发 / 回复）才被要求，写到一半点提交会先带着已输入的内容去登录（和协议同意，如果还没
同意过），完事后原样弹回来接着发，不会把写了一半的东西弄丢。群发不再要求先点一次"预览收件人"才能
发——受众筛选器默认收起、带一个能直接用的默认范围，不碰它也能直接写、直接发。

**导航**（6 项）：首页 · 祈福广场 · 传递善意 · 我的福袋 · 个人空间 · 审核台。
"传递善意"一页两块：上面写新祝福，下面"我的善意"（发出记录 + 状态）。个人空间底部有一个只读的
"你已传递 N 份善意"累计数（承接原「回响」页，无连续天数、无排行、不可变现）。

## 走一遍：访客首次善意（无需登录，本机浏览器一个窗口即可）

先按下面「P1 群发」或「P2 祝福请求」走一遍，让广场上有至少一条已发布的祈福（最好带一条回应），
再退出登录（顶栏「退出」）或换一个无痕窗口，试试访客视角：

| 步骤 | 看什么 |
|---|---|
| 打开首页 | 不需要登录、不弹登录墙。首屏直接是一条真实祈福的处境摘录 + 最新一条回应摘录（没有回应就写"还没有人回应，第一句可能就是你的"）。 |
| 点「回应这条祈福」/「看完整的回应」 | 前者进这条祈福的录音回应页（音频回应本身仍要求登录，见下方"这版没有的"之外的既有约束）；后者进详情页，文字全部读得到。 |
| 详情页点一段音频 | 提示"登录后可收听"，不直接放。登录后回到同一页，这条音频就能放了——权限模型是"广场公开回应，任何登录用户可播放"，不再局限于作者或收件人。 |
| 点「给附近的人写一段祝福」 | 直接进撰写页，不需要先登录。写完点「发送」，才被引导去登录（内容不丢），登录后如果还没同意过协议，接着被引导去协议页（内容还在），同意后自动送出。 |

## 走一遍：P1 群发（需要至少两个账号）

用两个浏览器（或一个正常窗口 + 一个无痕窗口）分别当**发送者**和**收件人**。

### 1. 收件人 A（无痕窗口）

| 步骤 | 看什么 |
|---|---|
| 登录 | 输昵称即可（占位登录）。 |
| 个人空间 → 位置 | 点「用浏览器定位」，或手填经纬度（如 `30.28` / `120.16`）。看到"位置已设置，可以群发"。 |
| 个人空间 → 性别 / 出生年 / 标签 | 选几个。这些是别人的受众筛选能命中的画像。 |

### 2. 发送者（正常窗口）

| 步骤 | 看什么 |
|---|---|
| 登录 → 个人空间 | 设位置（填一个离收件人几百米～几公里的坐标，如 `30.2741` / `120.1551`）。 |
| 传递善意 → 形式 | 「文字」高亮；「语音 / 视频」灰着标"即将支持"。进页不再要求先同意协议——协议同意推迟到点「发送」那一刻。 |
| 传递善意 → 正文 | 顶部呼吸圆环 + 发心提示。范本只作参考、选不中、**粘贴被拦**。 |
| 传递善意 → 送给谁 | 默认收起，显示"默认送到 5 公里内，不碰这里也能直接发"；点「调整范围」才展开距离滑块 / 年龄区间 / 性别 / 标签。展开后可点「预览收件人」看"将送达 N 人（上限 10）"和最近几位，但这只是可选参考，不点也能直接发。 |
| 发送 | 不再因为"没预览过"被禁用。没同意过协议会先引导去协议页（同意后原样弹回、内容还在）；命中 0 人或超过上限时，提交后才提示具体原因（如"当前条件命中 0 人。试试：把距离从 5 公里扩大。"）。发出后到"已发送"页，显示"正在送往 N 位陌生人 · 校验中"。 |

### 3. 回到收件人 A

| 步骤 | 看什么 |
|---|---|
| 顶栏「我的福袋」 | hold（8 秒）+ 扫描后出现红色未读徽标。 |
| 我的福袋 | 看到祝福正文 + "来自 XX · 城市 · 约 N km 外"。福袋每 3 秒自动刷新。 |
| 回一段祝福 | 点「回一段祝福」→ 撰写页顶部变成"回一段祝福给 XX"，没有受众筛选，只发给对方一人，同样过校验。 |

### 4. 发送者验收其余

| 在哪 | 看什么 |
|---|---|
| 我的福袋 | 收到对方的回信。 |
| 「传递善意」下半「我的善意」 | 群发记录 + 状态 + "群发 N 人" / "回复"标签；可撤回 / 删除 / 续期。撤回后收件人福袋里那条变占位。 |
| 个人空间底部「你已传递 N 份善意」 | 送出祝福的累计数；无排行无积分、不可变现。撤回 / 删除 / 下架即时回撤，链接过期不回撤。 |
| 「审核台」 | 命中护栏词的祝福停在这里，"通过"后才投递。举报的高危祝福排在最前（优先级 90）。 |
| 公开链接 | "已发送"页有 `/p/:slug`，用来把这条祝福转发出去带人来平台——不是送达机制。访客免登录可看、可举报。 |

## 试试这些内容（P1）

> 下面几条要看到真实判定效果，得用 `BW_MODERATION=rule_based pnpm demo` 起——
> 默认的 `pnpm demo` 恒 pass，这些内容也会直接投递。

- 正常祝福（≥5 字）→ hold 后投递到福袋。
- 含"超度收费" / "加我微信" → 判 suspect，停在校验中、进审核台，人工"通过"后才投递。
- 含"刷单返利" / 刷屏（"啊啊啊啊啊……"）→ 判 violation，直接"未通过"，不投递。
- 正文写"祝好"（太短）→ 提交被拒（字数校验跟审核判定无关，`pnpm demo` 默认状态下依然生效）。

## 走一遍：P2 祝福请求 + 音频回应（需要至少两个账号）

浏览器要给麦克风权限（本机测试用真实麦克风；Chrome 也可以用
`--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` 启动参数免权限弹窗，
`e2e/playwright.config.ts` 就是这么配的）。

### 1. 求祝福的人 A

| 步骤 | 看什么 |
|---|---|
| 登录 → 个人空间 → 设位置 | 同 P1，匹配推送要用。 |
| 同意协议 | 同 P1，发布请求前必须同意过。 |
| 顶栏「祈福广场」→「发布一条祈福」| 写处境（如"最近考研压力很大，希望有人鼓励我"），可选附一段稿子，可选标签，可勾选**匿名发布**（广场 / 详情显示"一位朋友"、不带城市，不影响自己收到回应，发布后不能再改）。 |
| 发布 | 命中拉客护栏词（如"加我微信"）会**停在人工复核**，不进广场、不触发匹配，跟审核台通过后才公开——跟 P1 的祝福同一套护栏词表；匿名不影响这条，工单仍指向真实作者。 |

### 2. 回应者 B（另一个账号）

| 步骤 | 看什么 |
|---|---|
| 登录 → 个人空间 → 设位置 + 打几个标签 | 标签跟祈福的标签重合，会收到匹配通知（顶栏「我的福袋」旁的未读徽标）。 |
| 祈福广场（未登录也能看） | 列表显示处境摘要、标签、"已收到 N 条回应"，以及**最新一条回应的正文摘录**（尚无回应显示"还没有回应"）；完整回应列表仍只在详情页。点进某条 → 详情页看处境全文、稿子、已有回应（访客能读文字，音频要登录）；点「录一段祝福回应」。 |
| 回应页 | 看到 A 的处境 + 稿子（如果有）+ 一个**验证码**（如 `372`）；下面是录音组件——点「开始录音」看波形跳动（Safari 上 AudioContext 起不来时降级为无波形但仍能录），说话时说出验证码，点「结束录音」，**最短 4 秒**。P2 不接真实语音识别，下面文本框可以手动写一下刚才说了什么（**不强制**——不写也能发出去，只是没法自动确认你说了验证码，会转人工看一眼再决定要不要送达）；禁用的「发出这段祝福」按钮下方会列出"还差什么"。 |
| 提交 | 跳到反馈页：完整度 / 专注度 / 真诚度三个标签（不是分数），命中疑似、没听清验证码、或没填补充文字时会提示"转人工复核"（没填文字不等于内容有问题，只是没法自动核验，所以不会被判"未通过"，是转人工）。 |
| 详情页往返回复 | 每条回应下面能看到已有的回复、也能就地回一段文字给对方（请求人 ↔ 回应者两边都能发起），点「回复」提交，过审核 + hold 后出现在这条回应下方，读起来是连续对话，不是一次性的"求祝福-收祝福"就结束了。 |

### 3. 回到 A

| 在哪 | 看什么 |
|---|---|
| 祈福广场 →「我的祈福」筛选 → 点进那条祈福 | 打分完成、hold 结束后（demo 里几秒钟）在详情页看到 B 的回应（音频 + 转写），能直接播放；广场列表的"已收到 N 条回应"和最新回应摘录同步更新（写入时维护的聚合字段，不扫表）。回应也会进 A 的福袋。可以在「我的祈福」列表或详情页撤回（撤回后广场看不到，也不能再回应——撤回是终态，同 P1 的祝福；撤回后如果这条祈福还有更早的回应，广场摘录会退回到那一条）。换第三个账号 C 登录（不设位置也行），打开同一条详情页也能直接播放 B 的音频——权限模型是"广场公开回应，任何登录用户可播放"，不再局限于作者或收件人。 |
| 我的福袋 | 同一条音频回应也能直接在福袋里播放（不用跳去详情页），下面标"这段录音的文字记录："再接转写文字——文字和录音在视觉上是绑在一起的一条消息，不是两条不相关的内容。 |
| 「审核台」 | 命中护栏词的祈福也会出现在这里（跟祝福共用一个队列），标"祝福请求"，通过后才公开 + 触发匹配推送。 |

## 环境变量

P1：`BW_HOLD_SECONDS`、`BW_MAX_AUDIENCE`（群发人数上限）、`BW_AUDIENCE_MAX_RADIUS_KM`、`BW_BODY_MIN_LEN` / `BW_BODY_MAX_LEN`、`BW_LINK_TTL_DAYS`、`BW_DB`（`memory` / `pglite`）、`BW_PGDATA`、`BW_MODERATION`（`rule_based` 默认 / `always_pass`，`pnpm demo` 脚本恒设成 `always_pass`，见上方"起"一节）。
P2：`BW_AUDIO_MIN_DURATION_SEC` / `BW_AUDIO_MAX_DURATION_SEC`（录音时长上下限）、`BW_AUDIO_DIR`（本机音频落盘目录）、`BW_LIVENESS_SECRET`（挑战式真人校验的签名密钥，生产环境务必换成真随机值）。
都见 `server/src/config/app-config.ts` / `server/src/config/env.ts`。

## 这版没有的（见 BACKLOG）

真实微信授权、真实内容安全 API、真实语音识别（P2 靠回应者自己补充文字）、逆地理编码（经纬度 → 城市）、真实推送通道、视频祝福（推到 P3）、悬赏与资金（P3）、i18n 抽取、PWA。审核台任何登录用户都能进（`add-moderation-rbac` 已出 spec，等评审后落地）。
